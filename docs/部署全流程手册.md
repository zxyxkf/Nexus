## 一、前置准备

### 1.1 服务器需要安装的软件

| 软件 | 最低版本 | 作用 | 下载地址 |
|------|---------|------|---------|
| **Docker Desktop** | 4.20+ | 运行容器里的后端、数据库 | https://www.docker.com/products/docker-desktop |
| **Node.js**（可选） | 20 LTS | 仅开发机需要；服务器用 Docker，不需装 | https://nodejs.org |
| **Git**（可选） | 2.40+ | 拉代码用；也可以直接拷贝文件夹 | https://git-scm.com |

### 1.2 Docker Desktop 安装注意事项

1. 安装后**重启电脑**（Docker 需要开启虚拟化）。
2. 重启后 Docker 会自动启动，右下角任务栏出现鲸鱼图标。
3. 如果 Docker 启动失败，进 BIOS 打开 **VT-x/AMD-V** 虚拟化。
4. 打开 PowerShell 或 CMD，输入 `docker --version` 能看到版本号就是成功了。

### 1.3 服务器建议配置

- **操作系统**：Windows 10/11 专业版或 Windows Server 2019+
- **内存**：8GB 以上（Docker + MySQL 占约 2-3GB）
- **磁盘**：D 盘至少 50GB 可用（数据库和上传文件会持续增长）
- **网络**：固定局域网 IP（如 `192.168.101.32`），端口 `18632` 不被防火墙拦截

### 1.4 防火墙设置

服务器需要允许以下端口的入站连接：

- **18632**：后端 API + 前端页面
- **3307**：MySQL（仅限本机访问即可，不需要对外开放）

设置方法：
1. 打开"Windows 防火墙" → "高级设置"
2. 入站规则 → 新建规则 → 端口 → TCP → `18632, 3307`
3. 允许连接 → 下一步 → 命名 "Nexus" → 完成

## 二、文件迁移

### 2.1 需要从开发机拷贝的文件

把开发机上整个项目文件夹拷贝到服务器。项目根目录叫 `d-design-art-manager`，拷贝到服务器的位置建议为：

```
D:\NexusServer\d-design-art-manager\
```

### 2.2 哪些文件/文件夹**不用拷贝**（已经在 .gitignore 中排除）

| 不需要拷贝的 | 原因 |
|-------------|------|
| `node_modules/` | 几百 MB，Docker 构建时会自动重新下载 |
| `dist/` | Vite 编译产物，Docker 构建时重新生成 |
| `release/`、`release-v2/`、`release-new/` | Electron 打包输出，服务器不需要 |
| `logs/` | 旧日志，服务器会重新生成 |
| `upload/` | 旧上传文件，服务器有自己独立的存储 |
| `data/` | 旧数据库文件，服务器用全新数据库 |
| `backups/` | 旧备份 |
| `.git/` | Git 历史记录 |
| `test-results/` | 测试报告 |

> **最省事的拷贝方法**：直接在开发机上把项目文件夹里的 `node_modules`、`dist`、`release*`、`.git` 删除后再拷贝，减少传输量。

### 2.3 服务器上的最终目录结构

```
D:\
├── NexusServer\                 ← 项目根目录
│   └── d-design-art-manager\    ← 项目代码
│       ├── docker-compose.yml
│       ├── Dockerfile
│       ├── package.json
│       ├── standalone-server\
│       │   ├── .env.production  ← 后面要改
│       │   ├── server.js
│       │   └── ...
│       ├── scripts\
│       │   ├── backup.bat       ← 数据库备份脚本
│       │   └── update.bat       ← 一键更新脚本
│       └── ...更多文件
│
├── Nexus_BOX\                   ← 数据存储（与容器内目录挂载）
│   ├── backups\                 ← 数据库备份存放处
│   └── upload\                  ← （可选）文件上传目录
│
└── NexusUpdates\                ← 更新代码的临时存放处
    └── latest\                  ← 把最新代码放这里，运行 update.bat
```

## 三、配置修改

代码拷贝到服务器后，**必须修改以下配置**才能正常使用。

### 3.1 修改数据库密码

**文件位置**：`standalone-server\.env.production`

**为什么要改**：开发机的密码是默认的，生产环境必须换成你自己的。

**要修改的行**：第 15 行

```
修改前:
DB_PASSWORD=Nexus@2026!Prod#MyDB

修改后:
DB_PASSWORD=你自己设定的安全密码
```

> 密码建议：至少 12 位，包含大小写字母、数字、特殊符号。例如 `MyServer@2026#Safe`

### 3.2 修改 JWT 密钥

**文件位置**：`standalone-server\.env.production`

**为什么要改**：JWT 密钥用于生成用户登录凭证。用默认值会让别人能伪造登录。

**要修改的行**：第 8 行

```
修改前:
JWT_SECRET=nexus-prod-2026-my-secret-key-cmjy8520

修改后:
JWT_SECRET=随便打一串至少32位的乱码字符
```

> 生成方法：随便在键盘上乱打一串字母数字，越长越好。例如 `a7KpQ2xR9mW5sT3vY6bN8cL1dF4gH0jE`

### 3.3 核对 Docker 数据目录挂载

**文件位置**：`docker-compose.yml`

**为什么要核对**：Docker 容器内的数据库、上传文件需要映射到宿主机物理磁盘上。如果 D 盘路径不对，数据会丢失或存到错误位置。

**要核对的行**：第 17 行

```yaml
volumes:
  - nexus-logs:/app/logs           ← Docker 内部卷，不用改
  - nexus-uploads:/app/upload      ← Docker 内部卷，不用改
  - nexus-data:/app/data           ← Docker 内部卷，不用改
  - nexus-releases:/app/releases   ← Docker 内部卷，不用改
  - D:/Nexus_BOX:/app/host-uploads ← ← 核对这一行！
```

`D:/Nexus_BOX` 是 Windows 上实际存在的文件夹，容器内程序通过 `/app/host-uploads` 访问它。

**检查方法**：
1. 打开文件管理器，确认 `D:\Nexus_BOX` 文件夹存在。
2. 如果不存在，右键新建文件夹命名为 `Nexus_BOX`（注意大小写）。
3. 如果服务器 D 盘路径不同（如 E 盘），把第 17 行改为 `E:/Nexus_BOX:/app/host-uploads`。

### 3.4 核对 MySQL 端口

**文件位置**：`docker-compose.yml`

**要核对的行**：第 33-34 行

```yaml
ports:
  - "${DB_EXTERNAL_PORT:-3307}:3306"
```

含义：访问服务器 `3307` 端口，映射到容器内 MySQL 的 `3306` 端口。

**确认没问题**：如果服务器上 3307 端口已被其他程序占用，修改 `.env.production` 里增加一行 `DB_EXTERNAL_PORT=3308`（换一个不冲突的端口）。

### 3.5 Electron 客户端连接地址

**文件位置**：`electron\main.js`

**要核对的行**：第 64 行

```javascript
const DEFAULT_SERVER = 'http://192.168.101.32:18632';
```

**为什么要改**：打包出的桌面客户端默认连接这个地址。如果你服务器 IP 不同，必须改。

**改为你服务器的实际 IP**：

```
修改前:
const DEFAULT_SERVER = 'http://192.168.101.32:18632';

修改后:
const DEFAULT_SERVER = 'http://你的服务器IP:18632';
```

> 如果不需要 Electron 桌面客户端，这步可以跳过。

## 四、目录挂载核对

Docker 容器运行时，内部的所有数据（数据库、上传文件、日志）实际上存放在 Windows 宿主机上。部署前确认以下目录存在：

### 4.1 必须存在的文件夹

打开文件管理器，按以下路径逐一检查：

| 文件夹路径 | 用途 | 不存在怎么办 |
|-----------|------|-------------|
| `D:\Nexus_BOX\` | 容器与 Windows 之间的文件共享目录 | 右键 → 新建文件夹 |
| `D:\Nexus_BOX\backups\` | 数据库备份文件存放处 | 进入 Nexus_BOX 后新建 |
| `D:\NexusServer\d-design-art-manager\` | 项目代码目录 | 把拷贝过来的代码放在这里 |

### 4.2 Docker 内部卷说明（不用手动创建）

这些是 Docker 自己管理的卷，数据放在 Docker 内部，不用手动创建文件夹：

- `nexus-logs` → 容器内 `/app/logs`（程序运行日志）
- `nexus-uploads` → 容器内 `/app/upload`（用户上传的文件）
- `nexus-data` → 容器内 `/app/data`（SQLite 数据库文件）
- `nexus-releases` → 容器内 `/app/releases`（Electron 应用更新包）
- `mysql-data` → 容器内 `/var/lib/mysql`（MySQL 数据库存储）

### 4.3 查看 Docker 卷实际存放位置

如果想知道 Docker 把这些卷放在了 Windows 上哪个位置：

```bash
docker volume inspect nexus-logs
```

输出里的 `Mountpoint` 就是实际路径。

## 五、部署执行

### 5.1 首次部署（全新服务器）

打开 CMD（命令提示符）或 PowerShell，按顺序执行以下命令。

> 提示：每输入一行按一次回车。看到成功提示后再输入下一行。

**第 1 步：进入项目目录**

```bash
cd D:\NexusServer\d-design-art-manager
```

**确认**：输入 `dir` 能看到 `docker-compose.yml` 和 `Dockerfile` 两个文件。

**第 2 步：构建 Docker 镜像**

```bash
docker compose build
```

**确认**：等待约 3-5 分钟（首次较慢，后续快）。看到 `Successfully built` 或 `Successfully tagged` 就是成功了。

**第 3 步：启动所有容器**

```bash
docker compose up -d
```

**确认**：等待约 30 秒后，输入 `docker compose ps` 查看状态。两个容器的 `STATUS` 列都应该是 `Up` 或 `healthy`：

```
NAME                STATUS
nexus-mysql         Up (healthy)
nexus-server        Up (healthy)
```

**第 4 步：查看启动日志（确认没有报错）**

```bash
docker compose logs nexus-server
```

**确认**：日志里应该有 `[DB] MySQL 模式已激活` 和 `Server running on port 18632`。

如果看到红色的报错信息，跳到 [常见报错排查](#73-常见报错快速排查)。

### 5.2 启动成功后的第一个测试

打开浏览器，访问：

```
http://服务器IP:18632
```

能看到 Nexus 登录页面，说明部署成功。

### 5.3 使用默认管理员账号登录

| 字段 | 值 |
|------|-----|
| 用户名 | `admin` |
| 密码 | `admin123` |

> 登录后请立即修改 admin 密码（右上角 → 修改密码）。

## 六、启动校验

部署完成后，按以下清单逐项检查。每项通过后打勾。

### 6.1 服务状态校验

**检查项**：容器是否启动且健康

```bash
docker compose ps
```

**通过标准**：
- `nexus-server` 的 STATUS 显示 `Up` 或 `healthy`
- `nexus-mysql` 的 STATUS 显示 `Up` 或 `healthy`
- 两个容器都没有 `Restarting` 或 `Exited`

### 6.2 健康检查接口

**检查项**：后端 API 能否正常响应

浏览器访问：

```
http://服务器IP:18632/api/health
```

**通过标准**：页面显示 `{"code":0,"msg":"ok",...}` 或类似 JSON 响应（`code` 为 0）。

### 6.3 数据库校验

**检查项**：MySQL 数据库是否正常连接和工作

```bash
docker compose exec mysql mysql -u d_design -p你的数据库密码 -e "SELECT COUNT(*) AS table_count FROM information_schema.tables WHERE table_schema='d_design_art';"
```

> 注意：把 `你的数据库密码` 换成 `.env.production` 里的 `DB_PASSWORD`。

**通过标准**：输出一个数字（表数量），不是报错信息。

### 6.4 登录流程校验

**检查项**：能否登录系统

1. 浏览器打开 `http://服务器IP:18632`
2. 输入 `admin` / `admin123`
3. 点击登录

**通过标准**：成功进入系统主界面，左侧看到菜单栏。

### 6.5 文件读写校验

**检查项**：文件上传功能是否正常

1. 登录后，尝试创建一个任务并上传一张图片
2. 或者：在左侧菜单找一个已有任务，查看附件/图片能否正常显示

**通过标准**：图片能正常加载和预览。

### 6.6 接口功能快速校验

在浏览器中依次访问以下地址（需要先登录拿到 Token；更简单的方式是直接在系统里操作）：

| 测试内容 | 系统内操作 | 预期结果 |
|---------|-----------|---------|
| 任务列表 | 点击"全量任务管理" | 显示任务表格 |
| 创建任务 | 点击"发布任务" → 填写 → 提交 | 提示"发布成功" |
| 仪表盘 | 点击"数据仪表盘" | 显示统计图表 |
| 用户管理 | 点击"用户管理" | 显示用户列表 |

### 6.7 自动更新校验（仅 Electron 桌面端）

**检查项**：客户端能否检测到更新

1. 把打包好的 `.exe` 安装到一台测试电脑
2. 在服务器 `D:\Nexus_BOX\` 下建立 `releases` 文件夹结构（参考 electron-updater 文档）
3. 启动客户端，等待 5 秒后查看是否弹出"发现新版本"提示

**通过标准**：能检测到更新或显示"当前已是最新版本"（日志中能看到更新源连接成功的记录）。

## 七、日常后续运维

### 7.1 代码迭代更新

日常更新代码时，使用项目自带的**一键更新脚本**，无需手动敲命令：

#### 方式一：双击运行（推荐，最简单）

1. 把最新代码放到 `D:\NexusUpdates\latest\`（确保里面有 `docker-compose.yml`）
2. 双击 `scripts\update.bat`
3. 等待自动完成（约 3-5 分钟），最后看到 `Nexus 更新完成！`

**脚本干了什么**（每一步自动完成）：
1. 检查 Docker 运行状态和磁盘空间
2. 自动备份当前数据库
3. 同步新代码（自动保留你的 `.env.production` 配置文件）
4. 停止旧容器
5. 重新构建镜像并启动
6. 等待服务就绪，健康检查验证
7. 如果启动失败，自动回滚并恢复数据库

#### 方式二：手动更新

如果自动脚本不行，手动执行：

```bash
cd D:\NexusServer\d-design-art-manager

# 1. 备份数据库
双击 scripts\backup.bat

# 2. 停容器
docker compose down

# 3. 把新代码覆盖到项目目录（注意保留 .env.production）

# 4. 重新构建并启动
docker compose build --pull
docker compose up -d
```

### 7.2 数据备份

#### 日常备份（双击运行）

双击 `scripts\backup.bat`，自动完成：
- 备份 MySQL 到 `D:\Nexus_BOX\backups\`
- 备份 SQLite 到同一目录
- 自动删除 10 个之前的旧备份

#### 备份文件命名规则

```
mysql_20260525_143022.sql   → MySQL 备份（日期_时间.sql）
sqlite_20260525_143022.db    → SQLite 备份（日期_时间.db）
```

#### 建议备份频率

| 数据量 | 建议频率 |
|-------|---------|
| 正常使用 | 每天 1 次 |
| 大量任务 | 每天 2-3 次 |
| 发薪前后 | 操作前各备份 1 次 |

#### 恢复数据（紧急情况）

```bash
# 进入项目目录
cd D:\NexusServer\d-design-art-manager

# 先停掉应用
docker compose stop nexus-server

# 恢复 MySQL（把下面文件名换成你要恢复的备份文件）
docker compose exec -T mysql mysql -u d_design -p你的数据库密码 d_design_art < D:\Nexus_BOX\backups\mysql_20260525_143022.sql

# 重启
docker compose start nexus-server
```

### 7.3 常见报错快速排查

#### 错误 1：`docker: command not found`

**意思**：Docker 没装或没启动。

**解决**：
1. 检查右下角有没有鲸鱼图标
2. 没有的话去开始菜单找 "Docker Desktop" 启动
3. 等鲸鱼图标稳定后（不再转圈），重试命令

#### 错误 2：`port is already allocated`（端口冲突）

**意思**：18632 或 3307 端口被其他程序占用了。

**解决**：
```bash
# 查看谁占用了端口
netstat -ano | findstr :18632
netstat -ano | findstr :3307

# 记下 PID（最后一列的数字），到任务管理器 → 详细信息 里找到并结束那个进程
```

#### 错误 3：`Can't connect to MySQL server`

**意思**：后端连不上数据库。

**解决**：
```bash
# 查看 MySQL 容器状态
docker compose ps mysql

# 如果 mysql 状态不是 Up/healthy，看 MySQL 日志
docker compose logs mysql

# 常见原因：MySQL 容器还没初始化完，等 30 秒再试
```

#### 错误 4：`JWT_SECRET` 相关报错 / Token 验证失败

**意思**：所有用户登录都失败。

**解决**：确认 `.env.production` 里的 `JWT_SECRET` 和部署时一致。如果改过 JWT_SECRET，需要让所有用户重新登录。

#### 错误 5：页面打开一片空白 / 加载不出来

**意思**：前端文件没构建或 Nginx 配置有问题。

**解决**：
```bash
# 重建 Docker 镜像（会重新编译前端）
docker compose build --no-cache
docker compose up -d
```

#### 错误 6：上传文件失败

**解决**：
1. 确认 `D:\Nexus_BOX` 文件夹存在
2. 确认 `docker-compose.yml` 里第 17 行挂载路径正确
3. 查看日志：`docker compose logs nexus-server | grep -i upload`

#### 错误 7：容器不停重启（Restarting）

**解决**：
```bash
# 查看完整日志
docker compose logs nexus-server --tail=100

# 常见原因：数据库连不上、.env 配置错误、端口冲突
# 根据日志里的错误信息对照上面几项排查
```

### 7.4 日常维护命令速查表

| 操作 | 命令 |
|------|------|
| 查看容器状态 | `docker compose ps` |
| 查看后端日志 | `docker compose logs nexus-server --tail=50` |
| 查看数据库日志 | `docker compose logs mysql --tail=50` |
| 重启后端 | `docker compose restart nexus-server` |
| 完全重启所有服务 | `docker compose down && docker compose up -d` |
| 查看磁盘占用 | `docker system df` |
| 清理旧镜像缓存 | `docker system prune -a`（释放磁盘空间） |
| 进入容器内部 | `docker compose exec nexus-server bash` |
| 进入 MySQL 命令行 | `docker compose exec mysql mysql -u d_design -p` |
| 数据库备份 | 双击 `scripts\backup.bat` |
| 代码更新 | 双击 `scripts\update.bat` |
