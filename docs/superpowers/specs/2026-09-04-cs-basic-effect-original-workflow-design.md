# 客服与基础美工效果图、原图及审核流程设计

**日期：** 2026-09-04  
**状态：** 已确认设计，待实施  
**范围：** 客服/基础美工任务列表、任务详情、作品审核、暂存任务、原图上传状态流转

## 1. 目标

本次调整解决四类问题：

1. 编辑后的款式图在列表中出现模糊或残缺，预览必须保持完整比例并使用原始文件。
2. 客服新增修改区的图片上传需要实时缩略图，而不是只显示文件名。
3. 客服和基础美工需要同时区分“效果图”和“原图”，详情页也要清晰区分首次上传、修改结果和原图。
4. 客服审核通过后先进入“待上传原图”，基础美工上传并明确完成后，任务才进入“已完成”和原有分值审核流程。

## 2. 术语与数据边界

### 2.1 文件类别

继续使用 `task_file`，按 `file_category` 区分：

- `style`：客服发布任务时选择的款式图。
- `work` 且 `reject_record_id` 为空：基础美工首次上传作品。
- `work` 且绑定 `reject_record_id`：某一轮修改后的效果图。
- `reject`：客服在某一轮修改中上传的要求附件。
- `original`：客服通过后，基础美工再次上传的独立源文件。本次新增类别。

原图允许多文件，文件类型包括图片、PSD、AI、ZIP 等源文件。原图不覆盖首次上传或修改记录，也不参与效果图的选择。

### 2.2 效果图

效果图是客服和基础美工列表中当前任务的最终视觉结果：从已完成的修改轮次中按轮次从新到旧取基础美工作品图片；没有已完成修改作品时，回退到首次上传作品图片。客服修改要求附件、款式图和原图都不能作为效果图。

### 2.3 原图

原图是客服最终通过后由基础美工上传的独立源文件集合。图片原图显示缩略图并可放大；PSD、AI、ZIP 等不可直接渲染的文件显示文件类型卡片。所有原图文件均保留上传时的原始文件名，列表和详情支持拖出、下载。

## 3. 状态流转

本状态只对 `task_group = 'cs'` 的任务启用：

```text
accepted -> doing
doing --客服修改--> rejected -> doing
doing --客服通过/批量通过--> pending_original
pending_original --分批上传原图--> pending_original
pending_original --完成上传--> finished -> 原有分值审核
```

- `pending_original` 的界面名称为“待上传原图”。
- 客服通过或批量通过时，不再直接写入 `finished`，也不提前进入分值审核。
- “完成上传”必须在任务至少存在一个 `original` 文件时才能执行；成功后在同一事务中写入 `finished`，并沿用原有分值审核状态与查询规则。
- `design`、`operator` 等其他任务组的审核、上传、完成状态保持现状，不受新状态影响。
- 现有撤回、撤销提交、修改历史和暂存任务继承逻辑保持不变；原图仅作为独立类别参与详情和删除清理。

## 4. 后端设计

### 4.1 数据库

- `task_info.status` 使用现有文本字段新增值 `pending_original`，不改变已有数据。
- `task_file.file_category` 接受新值 `original`，沿用现有文件名、路径、大小、类型、MIME、上传人和时间字段。
- SQLite 与 MySQL 使用同一迁移逻辑；迁移只扩展允许值/查询，不清空已有任务和文件。

### 4.2 服务和接口

1. `reviewTask` 与批量审核通过：当任务组为 `cs` 时将 `doing` 设置为 `pending_original`，保留作品、修改记录、申请分数和审核关联数据。
2. 新增原图分批上传接口：
   - 接收多文件，文件先落临时目录。
   - 校验当前用户为该任务的基础美工、任务状态为 `pending_original`、任务组为 `cs`。
   - 写入 `task_file.file_category = 'original'`，保留原始文件名。
   - 数据库写入失败时删除本批临时文件和已写入的文件记录，避免半成品。
3. 新增完成上传接口：
   - 只允许该任务基础美工执行。
   - 加任务锁并确认状态仍为 `pending_original`。
   - 确认至少存在一条 `original` 文件。
   - 事务内更新为 `finished`，设置完成时间，并让任务进入原有分值审核查询。
   - 重复点击返回幂等结果或明确提示，不重复生成记录。
4. 查询层新增独立文件选择器：
   - `getInitialWorkFiles`：首次作品。
   - `getEffectFiles`：最新已完成修改作品，回退首次作品。
   - `getOriginalFiles`：全部 `original` 文件，按上传时间和文件 ID 稳定排序。
   - `getWorkFiles` 不再把 `original` 混入效果图。
5. 任务简要信息、列表筛选、统计、导出、通知和未完成数量增加 `pending_original` 的显示映射，但只有客服/基础美工任务组使用该状态。

### 4.3 权限

- 原图上传复用基础美工现有 `task.upload.work` 权限，并由服务端额外校验任务归属和状态。
- 客服“修改”入口复用现有客服作品审核权限；该入口只创建/展开修改区，不直接修改任务状态。
- 不新增能绕过任务归属的权限；管理员的既有查看权限仍按原规则工作。

## 5. 前端设计

### 5.1 客服作品审核

- 操作列顺序为“查看作品 / 修改 / 通过”。
- “修改”直接打开详情并定位到“修改历史”的新增修改区，不再弹出第二个修改窗口。
- “通过”和批量通过后，列表不再显示已完成，而显示“待上传原图”的后续状态。

### 5.2 客服和基础美工任务列表

客服、基础美工相关列表统一调整：

- “作品预览”改名为“效果图”。
- “效果图”旁新增“原图”预览列。
- 图片缩略图采用固定容器和 `contain`，保持完整比例，不使用会裁剪主体的 `cover`。
- 缩略图点击可放大，图片和文件卡片均支持 HTML5 拖出并保留原始文件名。
- 没有文件时显示稳定占位，不把款式图或参考图当作效果图/原图。
- 操作列中的“上传作品”改为“上传”；`pending_original` 时显示“原图”按钮。

覆盖页面包括客服作品审核、客服我的任务、客服暂存任务、基础美工任务大厅、我的任务、待做任务、待审核任务及客服/基础美工全量任务。运营、运营助理、美工设计师等非目标页面只共享底层字段，不改变其展示和操作。

暂存任务列表额外新增“效果图”预览列，取当前最新效果图；继承、查看和原有暂存操作不变。

### 5.3 全量任务

客服/基础美工全量任务表格将“工作项目”和“分值”替换为“款式图”和“作品图”。作品图区域并列展示效果图和原图；原图中的不可预览源文件使用文件类型卡片。原有搜索、分页、排序和详情入口保持不变。

### 5.4 任务详情

仅客服/基础美工详情上下文调整：

1. 款式图区域右侧增加原图区域。
2. 原“作品图片”标题改为“首次上传”，只展示首次作品。
3. 修改历史继续按轮次折叠展示，最新轮次的基础美工作品用于列表效果图。
4. 原图图片可放大、拖出；PSD、AI、ZIP 显示类型卡片并支持拖出/下载。
5. `pending_original` 任务显示原图上传面板，支持分批添加和“完成上传”。

其他详情上下文的字段、标签、按钮和任务流转不改变。

### 5.5 修改区上传体验

- 客服新增修改和基础美工处理修改共用实时文件预览组件。
- 选择文件、拖入文件或悬停激活后粘贴截图，都立即在上传框下方生成缩略图。
- 保留删除、重试、上传进度和错误提示；尚未点击“完成”的本地预览不写入正式修改记录。
- 原有首次上传作品、已保存修改记录和申请分数不因打开/关闭新增修改区而清空。

## 6. 图片清晰度与文件拖出

### 6.1 清晰度修复

列表中当前固定小尺寸和 `cover` 会造成长图被裁剪，部分编辑结果看起来像残缺；预览链路还可能误用缩略图或旧文件。修复要求：

- 列表缩略图只负责布局，使用 `contain` 和稳定宽高，不改变源文件。
- 放大预览、详情预览、拖出预加载全部使用任务文件的原始预览/下载地址。
- 编辑器导出图片保持原始画布像素尺寸，不在保存或列表查询阶段二次压缩。
- 通过文件 ID 和上传时间稳定排序，避免多张图片因排序变化造成视觉错位。

### 6.2 拖出行为

- 图片文件拖出到桌面或文件管理器时使用下载 URL 和原始 `file_name`。
- PSD、AI、ZIP 等文件卡片同样设置拖出数据，并保留原文件名和扩展名。
- 拖出不改变任务状态，不触发删除或完成上传。

## 7. 错误处理与兼容

- 原图上传不允许空文件、非法路径、超出服务端安全上限或不支持的文件类型；错误只影响当前批次，不修改任务状态。
- 非任务所属基础美工、非 `pending_original` 状态、非客服任务组的原图上传请求统一拒绝。
- 完成上传没有原图时拒绝；已完成任务重复完成时保持幂等。
- 页面刷新或重新登录后，已保存原图、效果图和修改历史必须从数据库恢复；只有未点击完成的本地文件预览可以丢弃。
- 旧任务没有 `original` 文件时列表显示占位，详情不显示虚假的原图；旧任务状态和原有作品展示保持兼容。
- 删除任务时同时清理 `original` 文件记录和物理文件；删除首次/修改作品不得误删原图。

## 8. 验证计划

### 后端

- 状态机覆盖 `doing -> pending_original -> finished`，并确认其他任务组路径不变。
- 客服单条和批量通过均进入 `pending_original`。
- 基础美工可多次分批上传，完成上传前状态不变；完成后只生成一次完成状态和分值审核入口。
- 权限、任务归属、文件类型、空提交、重复完成、事务失败清理。
- 效果图、首次上传、修改记录、原图查询互不混淆。

### 前端

- 客服审核“修改”入口自动展开新增修改区，实时显示缩略图。
- 客服/基础美工列表及暂存任务显示效果图和原图列，空值和非图片文件显示正确。
- 详情页媒体分区和“首次上传”标题正确，原图图片可放大/拖出，源文件可拖出/下载。
- 待上传原图状态的按钮、上传面板、完成上传禁用条件和成功刷新。
- 运营、运营助理、美工设计师页面回归检查，确认无新增按钮、字段或状态污染。

## 9. 非本次范围

- 不改变素材库、系统配置或生产数据库。
- 不改变客服、基础美工之外其他角色的任务字段、审核权限和流转规则。
- 不将 PSD/AI/ZIP 强制转换成图片；不可预览文件只提供类型卡片和下载/拖出。
- 不执行构建、打包或远程仓库推送，除非用户另行明确要求。

## 10. 验收标准

1. 客服通过后任务明确显示“待上传原图”，而非“已完成”。
2. 基础美工可分批上传多种原图，点击“完成上传”后任务才进入已完成和分值审核。
3. 效果图、首次上传、原图和修改历史在列表与详情中各自独立，款式图不会冒充作品图。
4. 列表缩略图不再裁剪或残缺，放大和拖出得到清晰原文件。
5. 客服作品审核有“修改”快捷入口，新增修改上传实时显示缩略图。
6. 暂存任务显示效果图预览，原有继承流程保持正常。
7. 其他角色和非客服任务组的原有功能、权限、数据展示和任务流转不受影响。
