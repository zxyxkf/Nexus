# 客服与基础美工任务补充调整设计

## 目标

在不改变运营美工、运营助理、美工设计师等其他任务流程的前提下，完善客服暂存任务、客服基础美工款式图展示、款式图编辑器、基础美工批量提交，以及客服与基础美工之间的多轮修改沟通。

本次不构建、不打包、不推送远程仓库。开发和验证仅使用本地开发服务与本地 SQLite 数据库。

## 范围与角色隔离

- 修改历史只适用于 `task_group = cs` 的客服基础美工任务。
- 客服作品审核、基础美工任务详情、超级管理员/子管理员的客服基础美工全量任务详情使用同一套“修改历史”展示。
- 运营美工、运营助理、美工设计师的审核按钮、状态名称、详情字段、历史记录和任务流保持不变。
- 后端继续复用现有可靠的 `doing -> rejected -> doing -> finished` 状态流；`rejected` 在客服基础美工界面中显示为“修改中”，不修改全局状态含义。

## 一、暂存任务

### 列表

- 删除“工作项目”列，原位置改为“款式图”。
- 款式图仅取任务文件中 `file_category = style` 的图片，不能混入参考图或作品图。
- 展示行为与客服“我的任务”列表一致：首图缩略图、图片数量、点击预览全部款式图、首图可直接拖出。
- 其他列、搜索、筛选、查看和继承操作保持不变。

### 详情

- 暂存任务已经清空发布人，详情中的“发布人”固定显示“暂存”，不能根据当前登录人显示“我”。
- 新增独立的暂存详情上下文，避免修改普通客服“我的任务”的发布人显示逻辑。

## 二、款式图编辑器画布移动

- 在编辑器中增加显式“移动画布”工具。
- 开启移动工具后，按住鼠标左键拖动可平移整个 Fabric 视口；关闭后恢复正常的图层选择、缩放和元素拖动。
- 鼠标滚轮继续以指针位置为中心缩放。
- 还原原图时同时复位视口。
- 画布平移和缩放仅是查看状态，不写入编辑场景，也不改变保存成品的内容坐标。
- 保存前继续临时恢复单位视口导出完整图片，导出结束后恢复当前视口。

不采用拖动空白处自动平移，以免与图层选择冲突；不只依赖中键或键盘组合键，避免功能难以发现。

## 三、基础美工款式图列表

### 任务大厅

- 仅当当前角色是基础美工时，将“指定颜色”列替换为“款式图”。
- 使用与客服“我的任务”一致的首图、数量、全部预览和拖出行为。
- 美工设计师继续显示原“指定颜色”，运营助理页面保持原样。

### 我的任务、待做任务、待审核任务

- 三个路由共用 `basic/MyTasks.vue`，统一将“指定颜色”替换为“款式图”。
- 只显示 `file_category = style` 的任务款式图，作品预览继续只显示基础美工提交的作品文件。
- 其他列、上传、撤回、转移、筛选和任务状态逻辑保持不变。

## 四、批量提交

- 已匹配任务编号改为可点击链接。
- 点击后在当前页面上层打开该任务的原详情，不跳走页面、不清空已选文件、不丢失当前申请分值。
- 详情使用客服基础美工任务的 `cs-assignee` 上下文。
- 任务编号下方由“工作项目”改为“发布人：姓名”。匹配接口补充返回 `publisherName`，不返回无关敏感字段。
- 申请分值改用响应式、按任务 ID 隔离的状态，匹配列表刷新时保留已输入值。
- 申请分值规则与普通上传作品一致：默认 1 分、最小 1 分、步长 0.5、保留 1 位小数；提交时每个任务使用各自输入的分值。

## 五、客服与基础美工修改历史

### 发起修改

- 客服作品审核列表和详情中移除用户可见的“驳回”入口，原位置改为“新增修改”。
- “通过”和批量审核通过保持原功能。
- 点击“新增修改”打开提交框，客服可填写修改说明并上传多个文件，支持现有拖拽、选择和截图粘贴能力。
- 客服提交时，文字说明或附件至少填写一项。
- 新增仅服务于客服基础美工任务的 multipart“新增修改”接口，使文字、附件、修改记录和任务状态在一次请求中完成校验与保存；其他任务组继续使用原审核接口。
- 提交后任务进入基础美工的“修改中”状态，并出现在其待做/我的任务中。

### 基础美工回复

- 基础美工打开修改中的任务时，可在最新一轮修改记录中查看客服说明和附件。
- 重新提交时，修改后的作品文件必填；回复文字选填。
- 本次提交的回复文字和作品文件关联到当前最新修改记录，随后任务重新进入客服作品审核。
- 每次重新进入客服审核后，客服仍可通过任务，或继续发起下一次修改。

### 记录与展示

- 复用现有驳回记录及文件关联结构，保留历史数据；新增基础美工回复字段。
- 原 `reject_reason` 作为客服修改说明继续保存；原客服驳回附件作为客服修改附件；原基础美工重新上传文件作为基础美工作品。
- 界面统一改称“修改历史”“第 N 次修改”“客服修改说明”“客服修改附件”“基础美工回复”“基础美工重新上传”。
- 记录按次数递增且不可覆盖。最新一次默认展开，之前记录默认收起。
- 每条折叠标题显示修改次数、发起时间，以及“等待基础美工修改”或“已重新提交”的状态。
- 展开后使用左右双栏布局：左侧为客服说明和附件，右侧为基础美工回复和重新上传作品；窄屏改为单栏。
- 旧驳回记录直接按修改历史兼容展示，缺失的基础美工回复显示为空，不清理旧记录和旧文件。

### 数据库升级

- `task_reject_record` 增加可空的基础美工回复字段，SQLite 与 MySQL 初始化结构保持一致。
- 启动迁移只补充缺失列，不重写已有任务状态，不清空历史记录，不改变其他任务组数据。

## 数据流

1. 客服审核待审核任务，选择“新增修改”。
2. 前端以同一个 multipart 请求提交客服说明和附件。
3. 服务端校验该任务属于客服基础美工任务、当前用户有审核权限，并校验文字或附件至少一项。
4. 服务端创建第 N 次修改记录、关联客服附件，并将任务状态更新为 `rejected`。
5. 基础美工查看修改中的任务，填写可选回复并上传必填作品。
6. 服务端在同一次作品上传事务中，把回复和本次作品关联到最新未完成的修改记录，并将任务状态更新回 `doing`。
7. 客服再次审核，可通过完成，也可新增下一轮修改。

## 错误处理与并发

- 已不在待审核状态的任务不能新增修改。
- 不属于当前发布人的任务仍执行现有审核权限校验。
- 没有文字也没有附件时，客服不能发起修改。
- 基础美工没有作品文件时不能重新提交。
- 基础美工回复只允许写入该任务最新一条、尚未完成回复的修改记录。
- 重复提交或状态已经变化时返回明确错误，不创建重复修改记录。
- 客服新增修改时若任一文件保存或数据库写入失败，则请求整体失败，不留下只有状态或只有文字的半条修改记录。
- 基础美工作品上传失败时不写入回复、不改变任务状态，并明确提示失败原因。

## 验收标准

- 暂存列表显示款式图，预览和拖出与客服“我的任务”一致；详情发布人显示“暂存”。
- 基础美工任务大厅、我的任务、待做、待审核均显示正确款式图，作品预览未被款式图污染。
- 美工设计师任务大厅仍显示指定颜色，其他角色列表和详情无回归。
- 编辑器缩放后可使用移动工具把任意角落移到视口中央，保存结果不因视口平移而偏移。
- 批量提交的任务编号能打开详情，副标题显示发布人，分值修改后不回到 1，并按各任务输入值提交。
- 客服审核中不再出现“驳回”，可连续创建多次修改；基础美工每次回复后任务回到待审核。
- 客服、基础美工和客服基础美工全量任务详情均显示相同的修改历史；其他任务组仍保留原有语义和流程。
- 本地后端测试和任务页面浏览器回归测试通过；不生成 `dist` 或安装包。
