# 基础美工当月图片统计卡片设计

## 目标

在基础美工角色的个人统计页面，将“累计分值”和“总接单量”替换为“当月效果图”和“当月原图”，分别展示当前登录基础美工本月上传的两类文件数量。

## 范围

- 仅修改基础美工个人统计页面及其对应的个人统计接口。
- 其他角色的个人统计卡片保持现状。
- 不修改任务状态、任务流转、上传限制、文件存储和权限逻辑。

## 统计口径

- 数据来源为 `task_file`。
- 使用当前登录用户的 `uploader_id`，只统计当前基础美工本人上传的文件。
- 使用文件 `create_time` 判断是否属于当前自然月。
- `file_category = 'work'` 计入“当月效果图”。
- `file_category = 'original'` 计入“当月原图”。
- 不限制 `file_type`，因此 PSD、压缩包等非图片文件，只要归入对应类别也会计数。
- 其他 `file_category` 不计入这两个卡片。
- 没有记录时返回并展示 0。

## 实现方案

后端在 `task.service.js` 的基础美工个人统计分支中调用一个专用 DAO 查询，查询当前用户本月 `work` 和 `original` 文件数量，并将结果合并到 `getMyStats()` 返回对象：

```js
{
  current_month_effect_images: number,
  current_month_original_images: number
}
```

DAO 查询只负责筛选和计数，服务层负责计算当前月份边界并传入起止时间，避免依赖 MySQL/SQLite 不一致的日期函数。

前端 `src/views/basic/Stats.vue` 仅替换卡片配置中的两个字段和标签；`StatsPanel`、其余卡片及其他角色页面不变。

## 错误与兼容处理

- 查询失败沿用现有个人统计接口错误处理，不改变接口错误协议。
- 缺失统计字段时前端继续通过 `?? 0` 显示 0。
- 不新增数据库表或迁移，不影响生产数据库结构。

## 验证标准

1. 基础美工个人统计显示“当月效果图”和“当月原图”，不再显示“累计分值”和“总接单量”。
2. 当前月 `work`/`original` 文件数量与数据库记录一致，非图片文件也能计数。
3. 其他卡片、其他角色个人统计和任务流程无变化。
4. Node 语法检查、针对性测试和 `git diff --check` 通过。
