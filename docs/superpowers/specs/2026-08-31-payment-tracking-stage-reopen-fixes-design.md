# 打款跟踪阶段重开与条件展示修复设计

## 目标

修复打款跟踪阶段页面的四类问题，同时保持现有任务流转、权限、数据库结构和旧数据不变：

1. 重开或只读查看第二阶段时，“确认开启付费”和“微库存是否提报”正确回显。
2. 重开或只读查看第三阶段时，“是否做链接优化”正确回显。
3. 保存阶段所属的“链接状态”时，不覆盖当前页面尚未保存的阶段表单内容。
4. 第一阶段与第二阶段图片严格独立，第二阶段只展示 `potential_judgment` 分类图片。

## 根因

SQLite 将可空布尔字段返回为 `0/1`，后端阶段数据展示层只转换了字段名，没有将这些值转换成 `false/true`。Element Plus 单选项使用严格的布尔值，因此数据库中仍为 `1` 的字段在页面上表现为未选择。

保存“链接状态”后，前端使用接口返回的已保存阶段数据重建整个当前表单，导致尚未保存的本地输入被覆盖。

图片存储和查询已经按分类隔离。第一阶段使用 `product_main`，第二阶段使用 `potential_judgment`。需要通过回归测试锁定这一约束，避免完整记录中的其他分类图片被第二阶段图片组件展示。

## 设计

### 布尔值接口契约

后端记录展示层统一转换已知的可空布尔字段：数据库值为 `NULL` 时返回 `null`，`0` 返回 `false`，`1` 返回 `true`。本次至少覆盖：

- `testing.paidEnabled`
- `testing.weiStockReported`
- `monitoring.linkOptimized`
- `summary.exploded`

该转换只影响接口输出类型，不修改数据库值、表结构或保存逻辑，并兼容 SQLite 与 MySQL。

### 第二阶段条件展示

“店长付费确认”始终展示。

- `确认开启付费 = 是`：展示付费时间、推广信息、潜力款判断和图片上传区；付费时间必填。
- `确认开启付费 = 否`：隐藏上述区域，不删除其中已有数据和图片，且不允许进入下一阶段。
- 未选择：与“否”相同，不展示后续区域，也不允许进入下一阶段。

图片区域标题和上传组件标签统一为“图片上传区”。后端现有阶段推进校验继续作为最终约束，前端同时隐藏推进按钮并保留表单校验提示。

### 链接状态保存

保存或清空“链接状态”成功后，更新页面中的记录元数据、版本号、权限、时间线和链接状态，但保留当前 `formData` 草稿。页面主动加载、阶段保存、阶段推进和重开阶段时仍使用服务端阶段数据重建表单。

### 图片隔离

不新增图片复制或迁移逻辑。第二阶段图片组件只接收并展示 `category = potential_judgment` 且属于当前记录的图片；第一阶段的 `product_main` 图片不得出现在该区域。隐藏第二阶段后续区域时图片仍保存在原分类中，重新选择“是”后恢复显示。

## 验证

增加或调整自动化回归测试，覆盖：

1. 后端记录接口对阶段可空布尔字段返回 `true/false/null`。
2. 重开第二阶段后，付费确认和微库存选项正确回显。
3. 重开第三阶段后，链接优化选项正确回显。
4. 保存链接状态后，尚未保存的第二、第三阶段输入保持不变。
5. 付费确认选择“否”时后续区域隐藏、数据不被清除、不能推进；重新选择“是”后数据恢复。
6. 第二阶段只展示 `potential_judgment` 图片，不展示 `product_main` 图片。

执行现有打款跟踪前后端测试和任务页面回归测试。不执行应用打包，不连接生产数据库，不推送远程仓库。
