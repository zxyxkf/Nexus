# 基础美工仪表盘与统计改进设计

## 目标

统一客服/基础美工全量任务的状态、搜索和批量文件下载体验，补充基础美工仪表盘的修改中、月度图片和日图片统计，并更新基础美工个人统计卡片。

## 范围与边界

- 修改客服基础美工全量任务、基础美工仪表盘、基础美工待做任务和基础美工个人统计。
- 其他全量任务分组、其他角色的统计页面和任务页面保持现有展示与逻辑。
- 不修改任务状态机、任务流转、上传流程、文件存储、权限模型或数据库表结构。
- 所有图片统计使用现有 `task_file` 数据，不新增迁移。
- 批量下载只筛选现有 `task_file` 文件，不改变文件存储或命名。

## 功能设计

### 1. 客服基础美工全量任务状态文案

仅当全量任务分组为客服基础美工时：

- `doing` 显示“审核中”。
- `rejected` 显示“修改中”。

运营、美工等其他分组继续使用现有状态文案。

状态筛选选项也按任务分组隔离：只有客服基础美工分组显示“待上传原图”（`pending_original`）；运营美工分组不显示该选项。

### 2. 客服基础美工全量任务搜索

客服基础美工全量任务的搜索框支持以下字段：

- 任务编号 `task_no`
- 标题 `title`
- 款号 `style_number`
- 旺旺 ID `wangwang_id`

前端占位提示和后端 `queryAllTasks` 的客服分组查询保持一致。其他分组查询条件不变。

### 3. 基础美工仪表盘修改中卡片

在基础美工仪表盘“待审核”和“已完成”之间增加“修改中”卡片，读取客服任务分组中 `status = 'rejected'` 的现有统计值 `rejected_count`。不新增状态或字段。

### 4. 基础美工月度效果图/原图柱状图

基础美工仪表盘新增两个分组柱状图：

- “基础美工本月效果图&原图数量”
- “基础美工上月效果图&原图数量”

横轴为启用状态的基础美工人员，每位人员有“效果图”和“原图”两组不同颜色的柱子。统计来源为 `task_file`：

- `uploader_id` 对应基础美工用户。
- `file_category = 'work'` 计为效果图。
- `file_category = 'original'` 计为原图。
- 不限制 `file_type`，因此对应分类下的非图片文件也计数。
- 使用 `create_time` 的自然月边界区分本月和上月。
- 其他文件分类不计入。

后端返回按用户聚合的当前月和上月数据，前端仅负责图表渲染。

### 5. 基础美工效果图/原图日统计

基础美工仪表盘新增“基础美工效果图&原图日统计”，布局沿用现有基础美工日统计：

- 行为基础美工人员。
- 列为当前月份的日期。
- 单元格显示“效果图 / 原图”数量。
- 数据按 `uploader_id`、`file_category` 和 `create_time` 的日期聚合。

该统计只增加展示，不改变现有日统计或任务状态点击逻辑。

### 6. 基础美工待做任务状态筛选

基础美工待做任务页面显示状态筛选控件：

- 空筛选时保持当前待做范围：`accepted,rejected,pending_original`。
- 选择具体状态时按所选状态查询。
- 状态文案使用“已接单”“审核中”“修改中”“待上传原图”“已完成”。

路由、权限和任务流转不变，仅调整筛选控件可见性和查询参数。

### 7. 基础美工个人统计卡片

基础美工个人统计页面：

- 将“累计分值”替换为“当月效果图”。
- 将“总接单量”替换为“当月原图”。
- 继续保留已完成、当月分值、今日分值、昨日分值和完成率卡片。

后端在基础美工个人统计分支返回：

```js
{
  current_month_effect_images: number,
  current_month_original_images: number
}
```

统计当前登录基础美工本月上传的 `work`/`original` 文件，不限制 `file_type`，按 `create_time` 的自然月边界计算；没有记录时返回 0。

### 8. 全量任务按文件类别批量下载

全量任务列表选中任务后点击“下载文件”时，增加可选的文件类别筛选；未选择类别时保持现有行为，下载选中任务的全部可下载文件。

- 客服基础美工全量任务仅提供：参考图、款式图、效果图、原图。
- 运营美工全量任务仅提供：参考图、作品。
- 下载筛选在前端按当前任务分组展示，不能把两组类别混合到同一菜单。
- 用户选择一个类别后，只下载选中任务中该类别的文件；没有匹配文件时返回现有的“无可下载文件”提示。
- 后端接收可选类别参数并按任务分组校验允许值：客服组允许 `reference/style/work/original`，设计组允许 `reference/work`；参数为空时不增加类别条件，维持原下载结果。
- ZIP 目录结构和文件名继续沿用现有规则，默认下载与现有功能一致。

## 数据流与错误处理

- DAO 提供按用户和时间范围统计 `work`/`original` 文件的查询，服务层计算本月、上月和日边界并组装仪表盘返回结构。
- 查询异常沿用现有统计接口的错误处理与响应协议。
- 前端对缺失统计字段继续使用 0 作为显示兜底。
- 不新增表、不执行迁移，不连接或修改生产数据库。

## 验证标准

1. 客服基础美工全量任务显示“审核中/修改中”，搜索可命中编号、标题、款号和旺旺 ID；运营美工全量任务不显示“待上传原图”，其他分组无变化。
2. 基础美工仪表盘显示“修改中”卡片、本月/上月分组柱状图和效果图/原图日统计，数值与 `task_file` 分类及时间范围一致。
3. 基础美工待做任务空筛选保持原有待做范围，选择筛选后结果正确。
4. 基础美工个人统计显示“当月效果图”和“当月原图”，不再显示累计分值和总接单量。
5. 全量任务下载未选择类别时与现有结果一致，选择类别时只包含允许的对应文件。
6. Node 语法检查、针对性测试和 `git diff --check` 通过，且无任务流转回归。
