# 统一任务详情与选品阶段页布局设计

## 背景

当前系统存在两套任务详情展示方式：

- 选品收集中的“来源任务”使用 `TaskDetail.vue` 弹窗，信息结构清晰，但弹窗会受外层页面滚动和层级影响，出现位置偏移、顶部被遮挡、整个页面一起滚动的问题。
- 作品审核、任务大厅、我的任务、审核记录、分值审核和后台全量任务等页面分别维护内联详情覆盖层，布局和功能实现重复，视觉不一致。

选品阶段详情页还存在网格背景干扰、表单分区不清晰，以及流程按钮位于页面底部、不便于重复操作的问题。

## 目标

1. 所有“详情”“查看任务”“查看作品”入口使用同一套任务详情视觉和交互。
2. 详情层固定在主内容区域中央，标题栏固定，只有详情正文滚动。
3. 保留各页面现有业务动作、权限判断、数据加载和文件操作，不给无关角色增加新功能。
4. 选品阶段详情页改为干净的白色分区布局，取消网格背景，并把流程按钮移到首行右侧。
5. 不修改后端接口、数据库结构、权限表或业务状态。

## 非目标

- 不重做任务列表、筛选栏、分页或侧边栏。
- 不改变任务审核、接单、提交、转移、开启打款等业务规则。
- 不新增角色权限。
- 不打包、不部署、不推送远程仓库。

## 方案选择

采用共享详情层方案：新增一个统一的任务详情层组件，集中负责容器布局、标题区、滚动区和通用任务内容；各页面通过插槽传入自己已有的操作按钮和少量专属内容。

未采用以下方案：

- 分别修改每个页面：会继续保留大量重复模板和样式，后续容易再次不一致。
- 全局覆盖 Element Plus 弹窗样式：定位、层级和滚动仍容易受页面结构影响，不能稳定实现图三所示的主内容区固定体验。

## 统一详情层

### 容器行为

- 详情层覆盖侧边栏右侧、顶部导航下方的主内容区域。
- 与主内容区域四周保持约 16px 间距。
- 详情层位于列表内容之上，但侧边栏和顶部导航保持可见。
- 打开详情后，外层列表保持原滚动位置且不可误操作。
- 详情层使用固定高度边界，不随内容增长撑高页面。
- 标题栏固定在详情层顶部，正文区域独立纵向滚动。
- 每次打开详情时正文滚动位置重置到顶部。
- 关闭详情后恢复原列表、筛选、分页和滚动位置。

### 标题栏

标题栏左侧展示：

- 任务标题或工作项目。
- 执行人。
- 当前状态。
- 上传提交时间等当前页面已有的重要摘要。

标题栏右侧展示当前页面允许的操作按钮和关闭按钮。统一详情层不硬编码角色判断或业务操作。

### 通用正文

正文按以下顺序展示：

1. 任务状态提示与时间线。
2. 基础信息，包括任务编号、状态、分值、数量、店铺、款号、颜色、发布人、执行人和时间等已有字段。
3. 任务描述、驳回原因或其他状态提示。
4. 参考图片和参考附件。
5. 作品图片和作品附件。
6. 当前任务类型已有的驳回记录或补充信息。

图片继续支持现有的预览、下载和拖拽能力，附件继续支持下载和拖拽。

## 页面操作边界

共享详情层只提供布局和内容展示能力，各页面继续控制自己的按钮：

- 运营美工作品审核：保留通过、驳回、开启打款和关闭。
- 其他审核页面：只保留该页面当前已有的审核操作，不自动增加开启打款。
- 基础美工和客服相关页面：只更换详情布局，不增加开启打款或其他新动作。
- 我的任务、任务大厅等页面：保留原有接单、提交、编辑、转移等操作及权限判断。
- 只读详情入口：只显示关闭，以及正文中的预览、下载和拖拽功能。
- 选品收集中的来源任务详情：默认只读，不显示审核或开启打款操作。

按钮是否展示仍由现有页面状态和权限条件决定，不在共享组件中重新实现权限规则。

## 选品阶段详情页

### 页面背景与分区

- 移除网格背景，改为纯白主内容面。
- 页面不使用嵌套卡片堆叠，使用留白、细分隔线和小标题组织内容。
- 信息及选品阶段保留基础信息、选品及上架、图片资料三个主要分区。
- 后续阶段沿用同一视觉结构，保持字段和业务分支不变。

### 首行布局

首行左侧展示：

- 返回按钮。
- 当前阶段名称与进行状态。
- 货号、店铺序号、店铺、策划人和来源任务等商品摘要。

首行右侧展示当前状态允许的流程操作：

- 保存本阶段。
- 进入下一阶段。
- 结束流程。

恢复流程、重开阶段等状态专属操作仍按现有条件显示，并与同组操作保持一致。

### 响应式规则

- 宽桌面保持表单的高效多列布局。
- 紧凑桌面减少表单列数，避免字段标签和输入框挤压。
- 首行空间不足时，操作按钮移动到标题下方的独立一行，不与标题或摘要重叠。
- 图片分区在较窄窗口下减少列数，图片名称和按钮不得溢出。

## 组件边界

统一详情层应拆分为以下职责：

- 详情外壳：负责主内容区域定位、遮挡、固定标题栏、正文滚动和关闭事件。
- 通用任务详情内容：负责时间线、信息表、描述、图片、附件和驳回记录。
- 页面操作插槽：由调用页面提供业务按钮及其 loading、禁用和权限状态。
- 可选扩展插槽：承载少数任务类型独有的内容，避免把页面业务写入共享组件。

现有 `useTaskDetail` 继续负责详情接口调用、数据标准化、图片预加载和打开状态。共享详情层不直接发起审核、接单、提交或开启打款请求。

## 状态与异常

- 详情加载期间保留触发按钮的 loading 状态。
- 详情请求失败时不打开空白详情层，沿用页面现有错误反馈。
- 审核或其他操作请求进行中时，相关按钮保持 loading，防止重复提交。
- 操作成功后沿用原页面的列表刷新、详情关闭或状态更新行为。
- 文件预览或下载失败继续使用现有错误处理，不影响详情层关闭。

## 验收标准

### 统一任务详情

- 所有任务详情入口展示同一套信息结构和视觉布局。
- 详情层固定在主内容区域，不遮到顶部导航后方，不偏离可视区域。
- 外层页面不随详情正文滚动，标题栏和操作区始终可见。
- 正文可独立滚动，并在每次打开时回到顶部。
- 关闭后保留原列表的筛选、分页和滚动位置。
- 基础美工和客服页面不出现开启打款。
- 运营美工作品审核仍按现有权限展示开启打款。
- 各页面原有操作、图片预览、下载和拖拽能力不回归。

### 选品阶段详情

- 页面不再显示网格背景。
- 三个主要流程按钮位于首行右侧。
- 所有阶段字段、分支、校验和图片功能保持不变。
- 1600x900 和 1280x720 视口下无横向溢出、遮挡或按钮重叠。

## 验证策略

- 扩展任务页面 Playwright 回归测试，覆盖所有详情入口的打开、关闭和原有操作可见性。
- 增加详情层内部滚动、固定标题栏、外层滚动锁定和重新打开回到顶部的测试。
- 增加角色与页面操作隔离测试，重点确认基础美工、客服没有开启打款，运营美工作品审核按权限显示。
- 更新打款跟踪 Playwright 测试，覆盖来源任务详情定位和选品阶段页首行按钮。
- 在 1600x900 与 1280x720 视口运行视觉和溢出检查。
- 运行现有任务页面与打款跟踪全量回归测试。
