# 全店铺打款查看权限扩展作品审核范围设计

## 背景

当前 `payment.view.all`（查看全部店铺打款数据）只扩大选品收集和打款记录的数据范围。作品审核中的打款任务范围仍按账号店铺隔离，导致临时承担跨店铺打款工作的普通角色无法处理其他店铺任务。

## 目标

将作品审核中的“可见任务范围”和“可执行操作”继续拆分：

- `payment.view.all` 控制与打款有关的作品审核任务范围。
- `payment.open` 控制开启打款和批量开启打款操作。
- 原有作品审核权限继续控制审核通过、驳回等任务审核操作。

## 权限行为

### 仅有 `payment.view.all`

- 可查看全部店铺的选品收集和打款记录。
- 不因该权限单独获得作品审核页面入口。
- 不可开启打款，也不可审核通过或驳回作品。

### 同时拥有 `payment.view.all` 和 `payment.open`

- 可进入作品审核页面。
- 可查看全部店铺符合开启打款条件的美工任务。
- 可对任意店铺的可用任务执行开启打款和批量开启打款。
- 不因这两个权限获得审核通过、驳回作品的权限。

### 已有作品审核权限的用户

- 原任务发布人或原本拥有作品审核权限的用户，继续按现有规则审核任务。
- 新增的全店铺可见范围只影响与开启打款有关的任务列表范围，不扩大普通任务审核权限。

## 实现范围

- 后端任务列表：将 `payment.view.all` 纳入作品审核打款任务的全店铺数据范围判断。
- 后端开启打款：允许同时拥有 `payment.open` 和 `payment.view.all` 的用户跨店铺开启打款。
- 前端：沿用现有作品审核页面和受限操作模式，不新增页面、不修改按钮布局。
- 权限定义、数据库结构和任务流转状态保持不变。

## 验证

- 普通角色仅有 `payment.open` 时，只能看到并开启本店铺任务。
- 普通角色同时拥有 `payment.open` 和 `payment.view.all` 时，可看到并开启其他店铺任务。
- 仅有 `payment.view.all` 时，不能调用开启打款接口。
- 上述普通角色不能调用单条审核或批量审核接口。
- 原任务发布人和原有作品审核角色的审核能力不回归。

## 非目标

- 不让 `payment.view.all` 自动包含 `payment.open`。
- 不让 `payment.view.all` 或 `payment.open` 自动包含任何 `task.review.*` 权限。
- 不改变店长审核、选品流程、打款记录或数据库表结构。
