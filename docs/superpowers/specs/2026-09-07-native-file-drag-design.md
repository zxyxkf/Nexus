# 桌面客户端原生文件拖拽设计

## 背景

当前客户端已经使用 Electron 的 `webContents.startDrag()` 将服务端文件缓存到本地临时目录后拖拽到桌面。缓存未准备好时，前端会退回浏览器标准拖拽数据（接口 URL、`DownloadURL` 和文本），因此拖入企业微信时可能被识别为一段带 token 的 URL 文本，而不是本地文件。

## 目标

- 所有当前已经支持拖拽到桌面的文件，继续支持拖入企业微信、Photoshop 等本地软件。
- 在 Electron 客户端中优先、稳定地使用本地文件拖拽，不向本地软件传递接口 URL。
- 客服角色和基础美工角色页面拖出的文件使用任务编号命名，并保留原文件扩展名。
- 其他角色和页面保持原上传文件名，不改变现有命名行为。
- 不修改服务器文件名、数据库数据或生产环境配置。

## 范围

纳入现有 `setupFileDrag` 流程的全部文件类型，包括参考图、款式图、效果图、原图、任务详情中的图片和附件，以及其他页面原本可拖拽到桌面的文件。

本设计只针对 Electron 桌面客户端。浏览器网页版继续保留浏览器原生拖拽降级行为，但不作为本次功能目标。

## 命名策略

拖拽组件必须显式传递命名模式，禁止根据发布人、文件类型或任务状态隐式推断。

### 客服和基础美工

- 有任务编号时：`任务编号.原扩展名`。
- 同一任务的多个文件使用稳定的 `_1`、`_2` 后缀，避免临时文件互相覆盖。
- 例如：`C202608280002.png`、`C202608280002_1.png`。
- 原始扩展名保持不变；非法 Windows 文件名字符只在客户端临时文件名中清理。

### 其他角色和页面

- 沿用原上传文件名。
- 仅清理 Windows 不允许的字符、尾部空格/句点和保留设备名，确保可以创建临时文件。
- 不因为同一任务、同一图片类型或当前用户角色而改成任务编号。

## 交互和数据流

1. 图片或文件进入可拖拽区域时，客户端后台预缓存对应文件到 Electron 临时目录。
2. 鼠标悬停、图片加载完成或可拖拽区域获得焦点时触发预缓存；同一文件和同一目标文件名不重复下载。
3. 拖拽开始时，若本地缓存已完成，则通过 IPC 调用 Electron `startDrag`，拖拽真实本地路径。
4. 若缓存仍在准备，Electron 客户端不再把接口 URL作为拖拽内容发送；提示“图片正在准备，请稍后再拖拽”，用户再次拖拽即可。
5. 桌面客户端保留必要的浏览器拖拽数据作为非 Electron 环境降级路径，但 Electron 成功启动本地拖拽时阻止该降级数据生效。
6. 临时文件仍按现有过期清理机制处理，不写入任务上传目录，不改变服务端原文件。

## 兼容性和错误处理

- 下载失败、token 失效或文件不存在时，保留现有错误日志，并显示可理解的“图片准备失败，请刷新后重试”提示；不向目标软件发送无效 URL。
- Electron 原生拖拽失败时，不静默伪装成成功；允许用户重新拖拽或使用原有下载入口。
- 非图片附件也按相同流程处理，保留其原始扩展名；Photoshop 等软件是否接受该文件由目标软件决定。
- 其他角色的命名策略默认为原文件名，新增命名模式必须由页面显式开启，防止跨角色回归。

## 实施边界

- 前端拖拽工具层负责传递文件、任务编号和命名模式。
- Electron 主进程负责安全文件名、临时路径、缓存和原生拖拽。
- 不改动任务流转、权限、上传接口、数据库结构或生产数据库。
- 不构建、不打包、不推送远程仓库，除非用户另行明确要求。

## 验证计划

- 在客服和基础美工页面分别拖出参考图、款式图、效果图、原图和附件，确认目标应用收到本地文件，文件名为任务编号加原扩展名。
- 在同一任务拖出多份文件，确认后缀稳定且文件不互相覆盖。
- 在运营、美工设计师、管理员等其他角色页面拖出相同类型文件，确认仍使用原上传文件名。
- 首次加载后立即拖拽、缓存完成后拖拽、下载失败后重试三种时序均验证。
- 确认桌面、企业微信、Photoshop 三类目标均不再收到带 token 的 URL 文本。
- 确认服务器文件名、数据库记录和生产连接均未被修改。
