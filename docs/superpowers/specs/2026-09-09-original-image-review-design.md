# 原图审核流程设计

## 目标

在客服与基础美工的任务流程中增加原图审核环节：客服通过效果图后，基础美工上传原图；原图上传完成后由客服审核，审核通过才进入已完成和后续分值审核，审核不通过或基础美工撤回则回到待上传原图。现有角色权限、任务隔离、效果图审核和其他任务流转保持不变。

## 范围与不变项

- 只针对客服发布的基础美工任务（`task_group = cs`）启用原图审核状态。
- 运营美工任务、运营助理任务、客服以外的任务不新增原图审核分支，继续沿用现有流程。
- 不新增数据库列；`standalone-server` 的 `task_info.status` 已是文本字段。只增加一个状态值 `pending_original_review`。
- 不修改生产数据库、生产上传目录或远程仓库；本次实现仅在本地工作区和本地开发数据库验证。
- 不改变已有“客服效果图通过 -> 待上传原图”的含义，也不删除或覆盖原图历史文件。
- 运营角色发布美工设计师任务的“款号”改为必填。该校验只作用于运营角色的设计任务发布表单和对应后端请求；客服、基础美工及其他角色的发布和编辑表单不改。

## 状态流转

```text
doing
  └─ 客服效果图审核通过
       ↓
pending_original
  └─ 基础美工完成原图上传
       ↓
pending_original_review
  ├─ 客服审核原图通过 → finished → 现有分值审核（如需）
  ├─ 客服审核原图不通过 → pending_original
  └─ 基础美工撤回 → pending_original
```

### 状态规则

- `pending_original` 仅表示可以继续上传原图；上传文件接口仍允许分批上传。
- “完成原图上传”只把状态改为 `pending_original_review`，不写 `finish_time`，不进入已完成统计，不创建分值审核待办。
- `pending_original_review` 必须存在至少一个当前原图文件，客服才可以审核原图。
- 客服审核原图通过时才写入完成时间，并沿用现有最终申请分值、分值审核状态和通知逻辑。
- 客服审核原图不通过时只回到 `pending_original`，保留原图文件和历史记录，基础美工可以继续上传或替换当前原图。
- 基础美工撤回原图审核只允许任务本人在 `pending_original_review` 执行；撤回不删除文件，不清空详情，只将状态回到 `pending_original`。
- `finished` 之后不允许原图撤回或再次审核。

## 后端接口与服务边界

### 新增接口

- `POST /api/task/review-original`
  - 请求：`{ taskId, action: "pass" | "reject" }`
  - 权限：沿用现有客服审核权限 `task.review.own` / `task.review.store` / `task.review.all` 及管理员角色，不新增绕过权限。
  - `pass`：校验任务为客服任务、状态为 `pending_original_review` 且存在原图，写入 `finished` 和完成时间，触发现有分值审核与完成通知。
  - `reject`：校验同上，将状态改为 `pending_original`，不清空文件，不生成驳回历史。

- `POST /api/task/withdraw-original`
  - 请求：`{ taskId }`
  - 权限：沿用基础美工上传权限 `task.upload.work`。
  - 只允许当前基础美工本人、客服任务、状态为 `pending_original_review`；成功后回到 `pending_original`。

### 现有接口调整

- `completeOriginalUpload()`：目标状态由 `finished` 改为 `pending_original_review`，移除其中提前设置完成时间和分值审核的行为。
- `reviewTask()`：保留当前效果图审核逻辑；客服通过效果图仍进入 `pending_original`。
- `undoSubmit()`：保持原有 `doing -> accepted` 逻辑，不复用到原图撤回，避免影响效果图流程。
- `attachAllowedActions()`：为 `pending_original_review` 暴露 `reviewOriginal`，为基础美工本人暴露 `withdrawOriginal`；其他状态的允许动作不变。

### 查询与统计

- 客服作品审核查询需要同时返回 `doing` 和 `pending_original_review`，但两种状态的操作按钮不同。
- 客服作品审核红点统计包含 `doing + pending_original_review`。
- 基础美工待办/我的任务统计将 `pending_original_review` 计入未完成任务；已完成统计只计入 `finished`。
- 运营美工相关统计、运营任务审核统计不纳入新状态。
- 导出状态映射和任务详情状态映射增加“待审核原图”。

## 前端交互

### 客服作品审核

- `doing` 行：显示现有查看作品、修改、通过等操作。
- `pending_original_review` 行：显示查看作品、审核原图；隐藏通过和效果图修改入口，避免重复操作。
- “审核原图”弹窗只提供通过/不通过两个明确按钮；不通过不要求额外填写原因。
- 批量审核通过只处理 `doing`：
  - `pending_original_review` 行复选框禁用；
  - 混合选择时只提交 `doing` 任务；
  - 批量数量不包含待审核原图；
  - 不增加批量审核原图，原图审核保持逐条确认。

### 基础美工

- 我的任务、待做任务状态筛选增加“待审核原图”。
- 任务处于 `pending_original_review` 时，操作列显示“撤回”；撤回后刷新为“待上传原图”，保留当前详情和文件历史。
- `pending_original` 继续显示原有上传原图入口；`finished` 不显示撤回。

### 其他列表

- 客服我的任务、待做任务、客服基础美工全量任务增加“待审核原图”筛选项。
- 暂存任务不增加该状态，因为待审核原图任务已有明确责任人，不应进入换班暂存池。
- 所有状态标签、颜色、导出文字统一显示“待审核原图”。

### 运营发布任务款号校验

- 运营角色发布美工设计师任务的“款号”显示必填星号，提交空值时阻止提交并提示“请填写款号”。
- 后端发布接口根据当前用户角色和设计任务类型执行同样校验，防止绕过前端提交空款号。
- 客服发布任务、运营助理发布任务、其他角色编辑任务以及历史任务不受影响。

## 权限与数据隔离

- 原图审核使用现有客服审核权限和店铺/本人任务范围判断，不扩大可见任务范围。
- `reviewOriginal` 必须复用现有 `reviewTask` 的任务可见性校验，不能仅凭按钮隐藏来保证权限。
- 原图撤回必须校验 `designer_id` 等于当前用户，管理员不通过该接口替普通美工撤回；管理员如需处理使用现有管理流程。
- 状态变更在事务中完成，避免审核动作成功但完成时间、分值审核或通知未同步的半完成状态。

## 错误处理与兼容

- 重复点击审核、过期页面提交或状态已变化时返回明确的 400 业务错误，不重复写完成时间、不重复创建分值审核记录。
- 没有原图时禁止完成上传和原图审核，并提示先上传原图。
- 效果图审核、原图上传、原图审核三类动作错误互不吞并，保持现有错误码和前端消息提示模式。
- 旧任务不会被批量迁移；已有 `finished`、`pending_original` 等状态按原值继续工作。只有新完成的原图上传进入 `pending_original_review`。

## 测试设计

### 单元测试

- 状态机增加并验证：
  - `pending_original -> pending_original_review`
  - `pending_original_review -> finished`
  - `pending_original_review -> pending_original`
  - `pending_original_review` 不能直接进入其他状态。
- 验证原图撤回只允许 `pending_original_review`，完成后不可撤回。

### API 测试

- 原图分批上传后完成上传进入 `pending_original_review`，且未写完成时间、未创建分值审核。
- 客服原图审核通过进入 `finished` 并触发现有分值审核逻辑。
- 客服原图审核不通过回到 `pending_original`，文件仍存在。
- 非任务可见客服、非本人基础美工、错误任务类型和错误状态均被拒绝。
- 原图审核重复提交、无原图审核、已完成任务审核均返回业务错误。
- 运营发布设计任务缺少款号被拒绝；有款号正常发布；客服发布任务的款号规则保持原状。

### 前端验证

- 状态筛选和标签在客服、基础美工、全量任务页面一致。
- `pending_original_review` 行的按钮与复选框行为符合设计，批量审核不会处理该状态。
- 基础美工撤回后列表、红点和详情状态即时刷新。

## 非目标

- 本次不增加“批量审核原图”。
- 本次不改变原图上传窗口、文件命名、存储目录和拖拽行为。
- 本次不改动运营角色除“款号必填”之外的发布表单字段。
- 本次不构建安装包、不修改生产数据库、不推送远程仓库。
