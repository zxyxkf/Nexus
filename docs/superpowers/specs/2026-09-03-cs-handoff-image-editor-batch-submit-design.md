# 客服任务交接、款式图编辑与基础美工批量提交设计

日期：2026-09-03

状态：已完成交互确认，等待文档复核

目标版本：未指定，本设计不自动修改版本号

## 1. 背景与目标

本次需求解决三个实际业务问题：

1. 客服换班时，未完成任务仍绑定上一班客服，下一班客服无法自然接手。
2. 客服选择款式素材后，只能通过任务描述说明修改位置，缺少直观的效果图编辑能力。
3. 基础美工完成多条任务后，需要逐条打开任务并上传作品，重复操作较多。

设计目标是在不改变原任务状态机、审核流程、分值流程和素材库原图的前提下，增加独立的任务交接、图片编辑和批量提交能力。

## 2. 范围

### 2.1 本次包含

- 客服角色的“上线 / 下线”业务状态。
- 客服侧边栏“暂存任务”页面及任务继承。
- 客服发布任务页的款式图可视化编辑器。
- 白底或近似纯色底叠加图片的一键透明底处理。
- 基础美工顶部全局栏的批量作品提交入口。
- SQLite 与 MySQL 的幂等字段迁移。
- 对应权限、接口、实时刷新和验证覆盖。
- 修复通用“作品预览”把 `style` 款式快照误当作接单人作品的问题。

### 2.2 本次不包含

- 不让浏览器关闭、断网或退出登录自动触发客服下线。
- 不使用 AI 模型处理人物、商品照片等复杂背景。
- 不修改素材库原图。
- 不改变现有任务编号生成方式。
- 不改变任务原有接单、提交、驳回、审核和分值审核规则。
- 不为暂存任务新增一套任务状态机。
- 不构建、不打包、不推送远程仓库，除非用户后续明确要求。

## 3. 总体方案

采用“扩展现有任务模型”的方案：

- 客服上线状态独立保存，不复用网络在线状态。
- 任务增加独立的暂存标记，不复用 `draft`、`wait`、`accepted`、`doing`、`rejected`、`finished` 等原状态。
- 暂存任务仍是原来的 `task_info` 记录，接单人、文件和任务状态不变。
- 图片编辑器使用成熟的 Fabric.js 管理画布元素、缩放、旋转、图层和导出。
- 批量提交先做文件名匹配预览，再按任务分别提交，复用原提交权限和状态校验。

## 4. 权限与导航

### 4.1 新权限

- `cs.handoff.tasks`：查看客服暂存任务页面。
- `cs.handoff.claim`：继承暂存任务。
- `cs.shift.toggle`：切换当前客服的上线 / 下线状态。

`cs_agent` 角色默认拥有以上权限。页面权限可以继续使用系统现有的“禁用默认权限”机制进行个人级调整。超级管理员沿用全权限规则。

### 4.2 菜单与路由

客服基础美工分区顺序：

1. 发布任务
2. 暂存任务
3. 我的任务
4. 作品审核

“暂存任务”显示当前暂存池数量角标。路由建议为 `/cs/handoff-tasks`，页面只对拥有 `cs.handoff.tasks` 的用户开放。

### 4.3 基础美工批量提交入口

“批量提交”按钮只对基础美工角色显示，放在顶部全局搜索框右侧。接口仍要求 `task.upload.work` 权限，不因按钮可见而放宽后端权限。

## 5. 数据模型与迁移

### 5.1 `sys_user`

新增：

- `cs_shift_status`：`online` 或 `offline`，默认 `online`。

该字段只表达客服业务班次状态，与 Socket 在线状态、登录状态分开。

### 5.2 `task_info`

新增：

- `handoff_status`：空字符串或 `pooled`，默认空字符串。
- `handoff_time`：进入暂存池的时间，可为空。

进入暂存时同时执行：

- `handoff_status = 'pooled'`
- `handoff_time = 当前时间`
- `publisher_id = NULL`
- `publisher_name = ''`

继承成功时同时执行：

- `handoff_status = ''`
- `handoff_time = NULL`
- `publisher_id = 当前客服 ID`
- `publisher_name = 当前客服姓名`

不额外保存或展示旧发布人。必要的操作追踪只写入现有业务日志。

### 5.3 款式图顺序与编辑副本

任务款式图继续保存为 `task_file.file_category = 'style'`。保存任务款式图时按发布页当前展示顺序写入，混合的原图副本和编辑副本不得改变顺序。

编辑副本通过款式图专用接口保存，不能复用通用作品上传接口，以免误触任务提交状态变化或删除其他作品文件。

### 5.4 迁移原则

- SQLite 和 MySQL 都增加相同语义的字段。
- 新增字段使用默认值，现有客服账号自动视为已上线。
- 现有任务自动视为未进入暂存池。
- 迁移可重复执行，服务器多次启动不会重置已有值。
- 迁移不改写现有任务状态、发布人、接单人和任务文件。

## 6. 客服上线 / 下线与任务交接

### 6.1 状态入口

顶部全局栏“客服专员”身份标签旁显示紧凑状态按钮：

- 已上线：绿色状态，可发布、审核、继承任务。
- 已下线：灰色状态，只能查看页面。

点击后立即切换，不弹二次确认。

### 6.2 手动下线

客服主动切换为下线时，在同一个数据库事务中：

1. 将当前客服的 `cs_shift_status` 改为 `offline`。
2. 查询该客服发布的 `task_group = 'cs'` 任务。
3. 排除 `status = 'finished'` 和 `status = 'wait'`。
4. 其余任务进入暂存池并清空发布人。
5. 事务提交后通过 Socket 通知客服页面和相关基础美工页面刷新。

如果任一步失败，用户状态和任务归属一起回滚。

### 6.3 下线期间的待接单任务

客服下线时，`wait` 待接单任务不进入暂存池，仍可在基础美工任务大厅被接单。

当基础美工接单时，后端在接单事务内检查原发布人的 `cs_shift_status`：

- 原发布人仍上线：按现有逻辑处理。
- 原发布人已下线：任务完成接单后立即进入暂存池，清空发布人，但保留新接单人和 `accepted` 状态。

### 6.4 下线后的操作限制

下线客服可以查看现有页面和任务详情，但以下操作由后端拒绝：

- 发布任务。
- 审核或驳回作品。
- 批量审核。
- 继承暂存任务。

限制必须同时存在于前端按钮状态和后端服务校验中。

### 6.5 暂存任务页面

页面只查询：

- `task_group = 'cs'`
- `handoff_status = 'pooled'`

所有拥有页面权限的客服看到同一个暂存池。页面沿用现有任务列表视觉样式，提供：

- 搜索任务编号、旺旺ID、款号。
- 按原任务状态筛选。
- 查看任务详情。
- 继承任务。

页面不提供审核、编辑或删除按钮。客服必须先继承，任务才进入其正常“我的任务 / 作品审核”流程。

任务详情权限只对 `handoff_status = 'pooled'` 的暂存任务额外开放。该权限不能用于查看其他客服尚未进入暂存池的普通任务。

### 6.6 继承并发控制

继承操作使用事务和行锁：

1. 校验当前客服为已上线。
2. 锁定目标任务。
3. 再次校验 `handoff_status = 'pooled'` 且发布人为空。
4. 写入新的发布人并清除暂存标记。
5. 通知当前客服、其他客服和接单人刷新。

两名客服同时继承时只有第一名成功，第二名收到“任务已被其他客服继承”的明确提示。

### 6.7 重新上线

客服重新上线时不自动取回其下线前的任务。暂存任务继续留在公共暂存池，任何已上线客服，包括原发布人，都可以手动继承。

## 7. 款式图可视化编辑器

### 7.1 打开方式与布局

客服在发布任务页双击已选款式图，打开固定居中的编辑弹窗：

- 左侧为画布。
- 右侧为工具和当前元素属性。
- 底部为撤销、重做、还原原图、取消和保存成品。
- 弹窗内部滚动，不带动整个页面。

画布支持鼠标滚轮缩放，建议范围为 20% 至 500%。重新打开时默认适应画布。

### 7.2 框选工具

右侧使用一个名为“框选工具”的下拉框，选项为：

- 矩形。
- 圆形 / 椭圆。
- 自由四边形。
- 箭头。

这些选项不再平铺成多个按钮。箭头只出现在“框选工具”下拉框中，不在“添加内容”区域重复出现。

### 7.3 独立图层

框线、文字和上传图片均为独立 Fabric.js 对象：

- 同一张图可添加多个对象。
- 对象可自由拖动。
- 对象可等比例缩放和旋转。
- 对象可复制、删除、上移和下移图层。
- 框线可调整颜色和粗细。
- 文字可调整内容、字号、文字颜色和背景色。

文字和图片不被框选区域裁剪，也不强制限制在框内。

### 7.4 上传图片与透明底

“添加内容”区域只包含“添加文字”和“上传图片”。

选中上传图片对象后显示：

- 一键透明底。
- 识别容差滑块。
- 恢复处理前图片。

透明底算法完全在浏览器本地执行：

1. 从图片四条边的像素开始。
2. 按颜色距离和容差查找与边缘连通的背景区域。
3. 只将连通区域透明化。
4. 不删除 Logo 内部与边缘不连通的同色区域。
5. 输出保留透明通道的 PNG 图层。

该能力定位为白底或近似纯色底 Logo 处理，不承诺复杂照片背景抠图。

### 7.5 保存成品

点击“保存成品”时：

1. Fabric.js 将当前画布导出为普通图片。
2. 发布表单中的当前款式图替换为编辑副本并显示“已编辑”标记。
3. 素材库原图保持不变。
4. 同款式的其他图片和其他任务保持不变。
5. 当前发布会话中同时保留该图片的 Fabric.js 图层数据，可以再次打开并继续调整。
6. 发布任务时，编辑副本与未编辑的原图副本按现有顺序保存为任务款式图。

任务发布成功后只保存合成后的普通图片，不保存可继续编辑的图层工程。接任务人员无需编辑器即可预览、下载和拖出。

### 7.6 保存失败保护

- 原图读取失败时不进入可编辑状态并提示具体原因。
- 画布导出或上传失败时保留当前编辑内容和原款式图。
- 不允许失败结果覆盖当前发布表单中的图片。
- 上传到任务的专用接口按事务写入文件记录，失败时清理已落盘的临时文件。

## 8. 基础美工批量提交

### 8.1 入口与面板

基础美工点击顶部“批量提交”按钮后，在按钮下方展开大尺寸下拉面板，不打开独立页面。

面板包含：

- 支持多选和拖拽的图片上传框。
- 匹配数量汇总。
- 按任务分组的匹配结果。
- 每条任务的申请分数。
- 未匹配或冲突文件区。
- 清空和确认提交按钮。

添加文件后只读取本地文件名和基本信息，不立即上传文件内容。

### 8.2 可匹配任务

只允许匹配：

- 当前登录基础美工本人名下的任务。
- `task_group = 'cs'`。
- 当前原流程允许提交作品的状态，即 `accepted` 或 `rejected`。

`doing`、`finished`、他人任务和其他任务分区均不得通过批量入口提交。

### 8.3 文件名匹配优先级

后端根据当前可提交任务校验文件名：

1. 先查找文件名中是否包含某条任务的完整系统任务编号。
2. 找到唯一任务编号时直接精确匹配，不再使用旺旺ID。
3. 没有任务编号时，按完整旺旺ID进行兜底匹配。
4. 旺旺ID只对应一条可提交任务时允许匹配。
5. 同一旺旺ID对应多条可提交任务时标记冲突，禁止提交，并提示改用任务编号命名。
6. 文件名包含多个有效任务编号时同样标记冲突。

任务编号由系统自动生成，用户只需要让作品文件名包含该编号。

### 8.4 分组与申请分数

- 多个文件匹配同一任务时归入同一任务分组。
- 每个任务分组独立显示申请分数输入框。
- 申请分数默认 1 分，可逐任务修改。
- 原有“大于 1 分需要组长审核”的逻辑保持不变。

### 8.5 提交流程

1. 前端将文件名清单发送到匹配接口。
2. 后端返回可提交任务、匹配来源和冲突原因。
3. 用户确认分组和申请分数。
4. 前端按任务分组分别上传，限制合理并发，避免一次请求承载全部任务文件。
5. 每组复用原作品提交状态校验、文件保存、通知和分值逻辑。
6. 成功任务进入 `doing` 待审核状态。
7. 提交完成后面板保留逐任务结果。

### 8.6 部分失败与原子性

- 不要求整批全成或全败。
- 某条任务失败时，其他任务继续提交。
- 同一任务分组内的文件必须全部成功或全部失败。
- 数据库失败时回滚该任务的状态和文件记录，并清理该分组已经落盘的文件。
- 失败项保留文件、申请分数和错误原因，允许单独重试。
- 状态已变化、权限已变化、文件超限和任务不再属于当前用户时返回明确原因。

### 8.7 文件限制

- 批量入口只接受图片文件。
- 单文件大小继续使用现有上传配置。
- 每条任务的文件数量继续使用现有单任务上传数量限制。
- 面板总文件数不受单次请求数量限制，因为实际提交按任务拆分请求。

## 9. 作品预览分类修复

任务款式图使用 `file_category = 'style'`，不能参与接单人作品筛选。

通用作品辅助逻辑必须同时排除：

- `reference`
- `reject`
- `style`

因此客服“我的任务”和“作品审核”的“作品预览”只展示基础美工提交的 `work` 文件；款式图仍由独立款式图区域展示。该修复不改变文件内容、任务状态或任务流转。

## 10. 接口边界

建议新增独立接口：

- `GET /api/cs-shift/status`：查询当前客服业务状态。
- `POST /api/cs-shift/status`：切换上线 / 下线，并在下线时执行暂存事务。
- `GET /api/cs-handoff/tasks`：分页查询公共暂存池。
- `POST /api/cs-handoff/tasks/:id/claim`：继承单条任务。
- `POST /api/task/style-snapshots`：按顺序保存原款式图副本与编辑副本，不触发任务提交状态。
- `POST /api/task/batch-submit/resolve`：只根据文件名和当前用户任务返回匹配结果。

批量提交确认阶段可按任务复用现有作品上传接口；如果现有接口无法保证单任务文件落盘清理，则在服务层增加专用的单任务原子提交方法，但不另建任务状态机。

## 11. 实时刷新与通知

- 上线状态变化后刷新当前用户顶部状态。
- 任务进入或离开暂存池后刷新所有客服的暂存数量和列表。
- 继承后刷新新发布人的“我的任务 / 作品审核”。
- 任务在原客服下线期间被接单并自动暂存后刷新暂存池和接单人的任务页。
- 批量提交沿用原任务提交通知，一条任务只发送一次提交通知，不按文件重复发送。

## 12. 验证方案

### 12.1 权限与迁移

- SQLite 与 MySQL 新库建表字段一致。
- 旧库重复启动不会重置已有上线状态和暂存标记。
- 客服默认获得暂存页和状态切换权限。
- 禁用默认权限后路由和接口同时拒绝访问。

### 12.2 客服交接

- 下线只暂存非 `finished`、非 `wait` 的本人客服任务。
- 暂存后任务原状态、接单人和文件不变，发布人为空。
- 下线期间待接单任务被接单后自动暂存。
- 下线用户不能发布、审核、批量审核和继承。
- 重新上线不自动取回任务。
- 两人并发继承只有一人成功。
- 继承后任务进入新发布人的原有页面和权限范围。

### 12.3 图片编辑器

- 四种框选工具均能创建、移动、缩放、旋转和删除。
- 文字与图片不受框选区域裁剪。
- 图层上下移动、复制、撤销、重做和还原原图正常。
- 滚轮缩放不会带动底层页面滚动。
- 一键透明底只清除与边缘连通的近似背景。
- 容差变化可预览，恢复原图有效。
- 保存后只替换当前任务编辑副本，素材库原图不变。
- 编辑副本、未编辑款式图和预览顺序一致。

### 12.4 批量提交

- 完整任务编号优先于旺旺ID。
- 任务编号缺失时可用唯一旺旺ID匹配。
- 重复旺旺ID和多个任务编号均进入冲突区。
- 非本人任务、不可提交状态和非客服任务不能匹配。
- 多文件按任务正确分组，申请分数逐任务生效。
- 单任务失败不会留下部分文件或错误状态。
- 一条任务失败不影响其他任务。
- 成功任务进入原有待审核和分值审核流程。

### 12.5 回归检查

- 客服原发布、我的任务、作品审核和驳回流程。
- 基础美工原单条上传、重新上传、撤回提交和分值申请。
- 其他角色的任务发布、上传、审核和文件预览。
- 款式图独立展示，作品预览不再混入 `style` 文件。

## 13. 开发与交付约束

- 开发只使用本地后端和本地 SQLite 数据库。
- 不连接、修改或迁移生产数据库。
