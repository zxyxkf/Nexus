# 打款跟踪：选品收集设计

日期：2026-08-27

## 1. 目标

在现有系统侧边栏新增独立的“打款跟踪”分区。本次只实现“选品收集”及其归档页面“打款记录”，将《俪楚打款跟踪表3.0.xlsx》中选品收集表的长表流程改造成按商品、按阶段填写的业务页面。

设计目标：

- 普通用户只查看和协作编辑同店铺记录，超级管理员查看全部店铺。
- 用商品卡片和阶段页面替代88列宽表，降低连续填写的视觉负担。
- 阶段必须显式推进，未进入的阶段不可见且不可访问。
- 作品审核可直接开启打款并复制已有作品图片，减少重复上传。
- 图片使用独立、可配置的物理目录，不依赖原任务图片的生命周期。
- 新模块与现有任务、权限和系统配置只通过明确接口集成。

## 2. 范围

### 2.1 本次实现

- 侧边栏分区“打款跟踪”。
- 独立页面“选品收集”，只展示进行中的商品。
- 独立页面“打款记录”，只展示已结束的商品。
- 选品收集的六个业务页面：信息及选品、四个执行阶段、生命周期总结。
- 作品审核中的单条和批量“开启打款”。
- 打款图片独立目录配置。
- 店铺隔离、权限、阶段推进、结束、恢复、历史阶段重开和软删除。

### 2.2 本次不实现

- 主图创意收集。
- 评价收集。
- 市场分析。
- 将现有 Excel 历史数据导入系统。
- 生产发布、前端打包、Electron 打包或 Docker 构建。

未实现的三个业务页面本次不显示空入口。

## 3. 页面结构

### 3.1 侧边栏

“打款跟踪”分区本次包含两个独立入口：

1. 选品收集
2. 打款记录

两个页面拥有独立的查看权限。

### 3.2 选品收集

选品收集只展示 `in_progress` 记录，使用单行商品卡，不使用宽表格。每张卡片展示：

- 第一张产品主图。
- 店铺内序号、货号、产品 ID。
- 策划人、店铺、选品日期。
- 成本、售价和毛利。
- 当前阶段。
- 已实际进入的阶段时间线。
- “继续填写”入口。

支持按货号、产品 ID、策划人和当前阶段筛选。

时间线只渲染已进入阶段。未来阶段不显示，也不能通过 URL 或 API 直接访问。点击已完成节点进入只读详情，点击当前节点进入编辑页。

### 3.3 阶段详情

详情页采用左侧阶段时间线、右侧单阶段表单：

- 顶部显示商品主图、货号、产品 ID、策划人、店铺和当前状态。
- 左侧只显示实际进入的节点。
- 右侧只加载所选阶段的字段。
- 已完成阶段默认只读。
- 当前阶段可编辑。
- 有权限重开历史阶段时，该历史阶段临时可编辑，保存后重新锁定。
- 底部固定显示保存、结束流程和进入下一阶段等当前可用操作。

### 3.4 打款记录

打款记录只展示明确点击“结束流程”后的记录。商品卡片直接展示：

- 结束阶段。
- 结束类型。
- 流程中已有的业务原因或后续操作。
- 实际走过的阶段时间线。

示例：

- `结束于：第7-11天测款 · 未达潜力款 · 后续操作：直接关闭`
- `结束于：第12-18天数据监测 · 潜力款后放弃 · 原因：费比持续偏高`
- `结束于：第1-6天准备工作 · 主动结束流程`
- `总结阶段 · 流程完成`

系统不新增结束原因输入框。未达潜力款、潜力款后放弃等情况复用阶段内已有字段；其他阶段主动结束时显示“主动结束流程”。

## 4. 阶段模型与流转

阶段代码和顺序固定为：

1. `selection`：信息及选品
2. `preparation`：第一阶段，第1-6天准备工作
3. `testing`：第二阶段，第7-11天测款
4. `monitoring`：第三阶段，第12-18天数据监测
5. `breakout`：第四阶段，第12-30天打爆
6. `summary`：总结阶段，生命周期

所有阶段均可保存进行中数据。保存不会创建未来节点。只有“进入下一阶段”成功后，后端才创建下一阶段记录并更新当前阶段。

### 4.1 信息及选品到第1-6天

进入下一阶段前必须填写：

- 选品日期。
- 货号。
- 成本。
- 售价。
- 至少一张产品主图。
- 产品 ID。
- 选品方式。
- SKU 数是否不超过200。
- 上架日期。
- 上架类目。

策划人和店铺由系统确定，毛利由系统计算。“详细说明”“说明截图”“竞品主图”和“通过并设计主图”均选填。

“通过并设计主图”是普通布尔字段，默认不勾选，不记录确认人和确认时间，不参与阶段解锁。

### 4.2 第1-6天到第7-11天

字段：

- 6天评价数量：手动填写非负整数。
- 新品运营是否报名成功：是/否，未选择表示尚未填写。
- 店长审核是否开启付费：是/否。
- 付费时间。

店长选择开启付费且填写付费时间后，才允许进入第7-11天。选择否时停留当前阶段。

### 4.3 第7-11天到第12-18天

页面包含两个同级大项，不互相解锁，始终允许正常填写。

“直通车-测点击率”包含：

- 推广方式。
- 累计点击量。
- 平均点击率。
- 是否符合转全站标准。

“全站-测款”包含：

- 推广方式。
- 整体访客。
- 累计搜索访客。
- 真实成交人数。
- 平均点击率。
- 搜索访客占比。
- 是否符合潜力款标准。
- 不符合后续操作。
- 报备店长日期。
- 是否报备魏总备货。

搜索访客占比由系统按 `累计搜索访客 / 整体访客` 计算；整体访客为0或未填写时显示为空，不产生除零错误。“是否符合转全站标准”和“是否符合潜力款标准”均由使用者手动判断。

选择符合潜力款后，才允许进入第12-18天。选择不符合时显示选填的“不符合后续操作”，不创建后续节点；使用者仍需明确点击“结束流程”后才进入打款记录。

### 4.4 第12-18天到第12-30天

链接优化字段均选填：

- 改内销件数。
- 补评价条数。
- 标题优化时间。
- 问大家数量。
- 详情页优化时间。
- 素材是否精选。
- SKU 优化时间。
- 营销活动名称和让利比例。
- 20天内新品运营快速冲顶是否完成。

“20天内新品运营快速冲顶是否完成”保留为普通是/否选项，不参与阶段解锁。

推广调整不再限制为 Excel 中固定的三次。页面使用可动态新增、折叠展开的时间线，每条包含：

- 调整原因。
- 调整日期。
- 当前费比（7天）。
- 当前付款人数（7天）。
- 总预算。
- 投产/调整细节。
- 2-3天后数据反馈。

上述字段均选填。未选择“潜力款后放弃”时，使用者可进入第12-30天。选择放弃时，放弃原因和放弃时间必填，并且不创建后续节点；点击结束流程后显示“潜力款后放弃”及已有原因。

### 4.5 第12-30天到总结阶段

常规字段：

- 补坑产第一天、第二天、第三天。
- 进秒杀时间。
- 进超级打爆或极速爆单时间。
- 商品速爆时间。
- 是否符合强拉升标准（费比正常）。

选择符合强拉升标准时展开：

- 搜索涨幅趋势。
- 付款人数趋势。
- 当前预算。
- 当前费比（7天）。
- 当前付款人数（7天）。
- 调整日期。
- 总预算。
- 投产/调整细节。
- 3-5天后数据反馈。

选择符合时展开强拉升字段，详细字段均选填，随后可进入总结阶段。选择不符合时不显示强拉升字段，并允许进入总结阶段。未选择是否符合强拉升标准时可保存，但不能完成当前阶段。

### 4.6 总结阶段

字段全部选填：

- 是否打爆。
- 链接维护：大爆款、小爆款、强动销、次动销、盈利款、放弃款。
- 款式定义：大爆款、小爆款、强动销、次动销、盈利款、放弃款。
- 总结。
- 备注。

“链接维护”和“款式定义”是两个独立选项。点击“结束流程”并二次确认后，记录进入打款记录。

## 5. 创建记录

### 5.1 手动新增

- 策划人为当前登录用户。
- 店铺为当前用户所属店铺。
- 店铺内序号自动递增，每个店铺分别从1开始。
- 产品主图由使用者上传。

拥有选品收集页面权限的用户可手动新增和编辑同店铺记录，不另设手动新增权限。

### 5.2 从作品审核开启打款

运营角色的作品审核页面增加：

- 行操作“开启打款”。
- “批量审核通过”旁的“批量开启打款”。

开启打款不执行审核通过，两项操作相互独立。

自动映射：

- 原任务发布人 -> 策划人。
- 原任务发布人的店铺 -> 选品记录店铺。
- 原任务款号 `style_number` -> 货号。
- 原任务全部作品图片 -> 产品主图。
- 原任务 ID、任务编号 -> 来源追溯信息和详情入口。

同一来源任务只能创建一条选品记录。没有作品图片时按钮不可用。发布人未绑定店铺时不能开启并给出明确提示。

批量开启时，已开启、无图片、发布人无店铺或复制失败的任务逐条跳过，其他任务继续。完成后展示成功数量及每条跳过原因。

## 6. 图片与存储

增加独立系统配置键 `upload.payment_tracking_images_dir`，由超级管理员在系统配置页面修改。配置更新后刷新运行时存储配置。

图片类别：

- 产品主图。
- 详细说明截图。
- 竞品主图。

从作品审核开启时，全部作品图片物理复制到打款跟踪目录，不保存对任务图片的引用。第一张产品主图作为商品卡片封面，详情页提供与现有全量任务详情一致的完整图片预览。

复制采用完整成功原则：

1. 校验全部源图片存在且可读。
2. 校验目标目录存在或可创建且可写。
3. 将本次图片复制到唯一目录或唯一文件名。
4. 数据库事务成功后才返回创建成功。
5. 任意图片或数据库操作失败时，删除本次已复制文件并回滚记录。

配置目录变更只影响新图片。历史图片保存其原物理位置，不自动迁移。

## 7. 权限与店铺隔离

新增权限码：

- `payment.selection.view`：查看、手动新增和编辑选品收集。
- `payment.records.view`：查看打款记录。
- `payment.open`：作品审核中的单条和批量开启打款。
- `payment.manager_review`：第1-6天店长审核及付费时间。
- `payment.stage_reopen`：重开历史阶段、恢复其他人的已结束流程。
- `payment.delete`：软删除记录。

“进入下一阶段”不单独设置权限。

后端对每次查询和变更强制执行以下规则：

- 普通用户只能访问与自己 `store` 相同的记录。
- 同店铺用户可协作编辑进行中记录。
- 超级管理员可访问全部店铺。
- 店长审核字段只有 `payment.manager_review` 或超级管理员可修改。
- 记录策划人可结束和恢复自己的流程。
- `payment.stage_reopen` 持有人可结束、恢复和重开同店铺其他记录。
- 超级管理员可结束、恢复和重开全部店铺记录。
- 只有 `payment.delete` 或超级管理员可软删除权限范围内记录。

权限既控制菜单和按钮，也由 API 中间件和服务层再次校验，禁止只依赖前端隐藏。

## 8. 结束、恢复、重开和删除

### 8.1 结束流程

任一阶段均可结束，但只有记录策划人、拥有 `payment.stage_reopen` 的同店铺用户或超级管理员可操作。

结束时保存：

- 结束阶段。
- 结束类型。
- 从当前阶段已有字段派生的结束原因快照。
- 结束时间。

结束后状态变为 `ended` 并进入打款记录。

### 8.2 恢复流程

记录策划人可恢复自己的流程。拥有 `payment.stage_reopen` 的用户可恢复同店铺其他记录，超级管理员可恢复全部记录。

恢复后：

- 状态变回 `in_progress`。
- 回到结束前所在阶段。
- 原阶段数据和已进入节点全部保留。
- 记录从打款记录移回选品收集。
- 再次结束时重新生成结束信息快照。

### 8.3 历史阶段重开

重开只用于修正已完成阶段，不回退主流程：

- 当前阶段保持不变。
- 后续已填写数据不清空。
- 指定历史阶段临时解锁。
- 保存后重新锁定。

### 8.4 软删除

删除写入 `deleted_at`，默认查询不再返回记录。数据库数据和关联图片均保留，不执行物理删除。

## 9. 数据设计

不采用复制 Excel 的单张88列宽表，也不把所有阶段塞入一个无约束 JSON。使用核心记录、阶段状态和按阶段数据表：

- `payment_selection_record`：店铺、店铺内序号、策划人、来源任务、信息及选品字段、当前阶段、流程状态、结束快照、版本号和软删除字段。
- `payment_selection_image`：图片类别、路径、顺序、来源任务文件 ID。
- `payment_selection_stage`：已进入阶段、阶段状态、进入时间、完成时间和临时重开状态。
- `payment_selection_preparation`：第1-6天字段。
- `payment_selection_testing`：第7-11天字段。
- `payment_selection_monitoring`：第12-18天链接优化和放弃字段。
- `payment_selection_adjustment`：不限次数的推广调整记录。
- `payment_selection_breakout`：第12-30天字段。
- `payment_selection_summary`：生命周期总结字段。

约束：

- `(store, store_seq)` 唯一，序号分配必须在事务内完成。
- `source_task_id` 对非空值唯一，阻止重复开启。
- 阶段表 `(record_id, stage_code)` 唯一，阻止重复推进。
- 所有子表通过记录 ID 关联并级联禁止孤立写入。
- 金额和比例使用数值类型，产品 ID、货号和任务编号使用文本类型。
- 毛利和搜索访客占比由服务层统一计算，不接受客户端提交计算结果。

`payment_selection_record.version` 用于乐观锁。多人同时编辑时，版本不一致返回冲突，不静默覆盖他人数据。

## 10. 模块边界与代码落点

后端新增独立打款跟踪路由、服务和校验模块。模块只依赖：

- 当前登录用户和权限服务。
- 现有任务与 `task_file` 只读查询，用于开启打款。
- 存储目录工具，用于解析打款跟踪图片目录。
- 数据库引擎和事务。

现有任务模块不读取或修改打款跟踪内部表。作品审核只调用“从任务开启打款”接口。

前端新增：

- 选品收集列表页。
- 打款记录列表页。
- 共用的商品摘要卡和阶段时间线。
- 共用的阶段页面外壳。
- 六个聚焦的阶段表单。
- 动态推广调整组件。
- API 封装和阶段/权限常量。

接入现有文件：

- `src/config/menus.js`：新增分区和两个菜单项。
- `src/router/index.js`：新增权限路由。
- `src/views/shared/Review.vue`：新增单条和批量开启入口。
- `standalone-server/config/permissions.js`：注册权限。
- `standalone-server/services/permission.service.js`：沿用现有权限种子与覆盖规则。
- `standalone-server/routes/config.js`、`standalone-server/utils/share.js`、`standalone-server/config/database.js`：新增目录配置和自动建表。

## 11. API 行为

API 按资源和动作划分：

- 查询进行中列表和打款记录。
- 查询单条记录及允许访问的阶段。
- 手动创建记录。
- 从单个任务或任务集合开启打款。
- 保存信息及选品或指定阶段。
- 进入下一阶段。
- 结束流程。
- 恢复流程。
- 重开和重新锁定历史阶段。
- 上传、排序和查看打款图片。
- 软删除记录。

所有写操作在服务层重新校验权限、店铺、当前状态、阶段条件和版本号。开启、阶段推进、结束、恢复和删除均设计为幂等操作，重复请求不能创建重复记录或阶段。

## 12. 错误处理

- 字段校验失败返回具体字段错误，不推进阶段。
- 未来阶段访问返回不可访问，不泄露记录内容。
- 店铺或权限不匹配返回禁止访问。
- 乐观锁冲突提示“记录已被其他人更新，请刷新后重试”。
- 图片缺失、目录不可写、磁盘错误或数据库失败时回滚当前商品创建。
- 批量开启逐条隔离失败，汇总成功和跳过原因。
- 页面刷新后从数据库恢复状态、当前阶段和已进入节点。
- 前端不根据本地状态猜测阶段，始终以后端返回的允许节点和允许动作为准。

## 13. 数据库升级与环境隔离

在现有数据库初始化机制中同时添加 SQLite 和 MySQL 建表语句及必要索引。语句必须幂等，后端启动时自动执行：

- 本地开发使用项目本地 SQLite。
- 本地启动不得读取生产数据库连接配置。
- 服务器更新后首次启动自动创建新表和配置项。
- 不删除、不重建现有业务表，不迁移已有任务数据。

本功能开发和验证期间不执行 `npm run build`、Electron 打包或 Docker 构建。只有用户明确要求后才允许统一打包。

- 单条和批量开启、重复任务跳过。
- 图片全部复制成功和中途失败回滚。
- 所有阶段推进、条件分支、结束、恢复、历史重开和软删除。
- URL/API 直接访问未来阶段被拒绝。
- 多人编辑版本冲突不覆盖数据。

### 14.3 前端联调验证

- 进行中商品卡只显示实际进入阶段。
- 打款记录直接显示结束阶段和已有原因。
- 当前、历史和未来阶段的可见性及编辑状态。
- 作品审核单条和批量按钮权限、禁用状态和结果汇总。
- 多图上传、第一张封面、全量预览和目录配置更新。

所有验证使用本地后端和本地 SQLite，不连接或写入生产数据库。
