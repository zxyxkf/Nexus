# 打款跟踪流程调整设计

日期：2026-08-31

## 背景与目标

现实业务流程发生变化，需要调整现有“选品收集”和“打款记录”，同时保持打款记录外层时间线的现有样式、状态表达、节点点击交互、权限边界、结束/恢复能力和其他任务流程不变。

本次调整打款跟踪模块的前三个业务阶段，删除原第 5 阶段“第12-30天打爆”，并新增推广方式配置和两个多图场景。总结阶段保留原有字段与业务规则。

## 范围外事项

- 不修改打款记录外层时间线的视觉样式和交互方式。
- 不调整总结阶段 `summary` 的字段与业务规则。
- 不修改作品审核、任务流转及其他角色页面的既有逻辑。
- 不执行前端、Electron 或安装包打包。
- 不连接或修改生产数据库，不推送远程仓库。

## 总体方案

采用保留仍在使用的稳定内部阶段代码、重组业务流程的方案。删除 `preparation` 流程节点，保留其店长付费确认数据并迁入 `testing`；删除 `breakout` 流程节点及其旧业务数据。其余内部代码继续使用，减少对权限、恢复、时间线和接口的影响。

新流程为：

```text
信息及选品（selection）
  -> 第二阶段（testing）
  -> 第三阶段（monitoring）
  -> 总结阶段（summary）
```

打款记录外层继续使用现有横向时间线：矩形阶段节点、圆形序号、节点连线、完成/当前/结束状态颜色和点击节点进入详情的交互均保持不变。阶段序号按新流程重排为 1 至 4。尚未进入的后续节点仍不可见、不可点击。

## 信息及选品

### 选品时间

- 通过“作品审核 -> 开启打款”创建记录时，选品时间等于来源美工任务的发布时间。
- 后端创建记录时读取来源任务发布时间，与款号和主图一起写入选品记录。
- 时间值保持来源任务的原始格式，不额外重排或截断。
- 有来源任务的记录在前端只读展示选品时间。
- 没有来源任务的手动新增记录继续由使用者手动选择选品时间。
- 已存在且能关联来源任务的旧记录在升级时统一回填来源任务发布时间。
- 旧记录找不到来源任务时保留原选品时间，迁移不中断。
- 新建来源任务记录时，如果来源任务不存在或缺少发布时间，则拒绝创建并返回明确错误，不使用当前时间代替。

### 移除字段

从页面、接口字段映射和业务数据中移除：

- `通过并设计主图`
- `SKU 数是否不超过 200`

升级时清空这些字段的旧值。兼容列可以暂留在物理表中，但不再读取、返回或写入，确保数据库中不保留有效业务数据。

其他信息及选品字段、主图联动、手动图片上传与删除、来源任务详情和既有权限逻辑保持不变。

## 第二阶段

第二阶段使用内部代码 `testing`，页面标题不再显示“第7-11天测款”。页面采用现有详情页的分区式表单布局。

### 店长付费确认

从被删除的准备阶段迁入第二阶段顶部：

- 确认开启付费
- 付费时间

该分区保留原有店长审核权限。只有具备原店长审核权限或全局管理权限的用户可以修改。进入第三阶段前仍要求确认开启付费并填写付费时间。

### 推广信息

删除原“直通车测点率”和“全站推广”两个区域，合并为一个简洁的“推广信息”分区，只保留：

- 推广方式：可搜索下拉框，只允许选择超级管理员配置且已启用的选项，不允许使用者临时输入新值。

推广方式为选填。旧记录中原先手工填写的推广方式在升级时清空，不自动导入配置项。

彻底移除并清空旧值：

- 点击量
- 点击率
- 是否符合直通车测试标准
- 全站推广方式
- 整体访客数
- 搜索访客数
- 搜索访客占比
- 付款人数
- 平均点击率

### 潜力款判断

保留：

- 是否符合潜力款
- 不符合后续操作，仅选择“不符合”时显示，继续允许不选
- 店长提报日期
- 微库存是否提报

新增“潜力款判断图片”上传区：

- 选填，可上传多张图片。
- 支持拖拽、选择、预览、排序和删除。
- 当前处于第二阶段时可增删；阶段完成后只读；重开第二阶段后恢复编辑。

只有选择“符合潜力款”才能进入第三阶段。选择“不符合”时只能结束流程，继续沿用既有“不符合后续操作”生成打款记录结束说明。

## 第三阶段

第三阶段使用内部代码 `monitoring`，页面标题不再显示“第12-18天数据监测”。

### 链接优化

删除原“运营动作”整个区域及其全部旧数据，替换为：

- 是否做链接优化：是/否，选填，默认不选。

移除并清空的原运营动作数据包括改内销件数、补评价条数、标题优化时间、问大家数量、详情页优化时间、素材是否精选、SKU 优化时间、营销活动名称、让利比例和 20 天内新品运营快速冲顶是否完成。

### 链接状态

原“阶段判断”改名为“链接状态”，选项改为：

- 保投产
- 持续打爆

移除放弃原因和放弃时间及其旧数据。页面允许在未选择链接状态时暂存，但执行流程操作前必须选择：

- 选择“保投产”时只能结束流程，不允许进入下一阶段。
- 选择“持续打爆”时允许直接进入总结阶段。
- 未选择时不能结束，也不能进入下一阶段。

选择“保投产”并结束后，打款记录时间线展示：

```text
第三阶段结束 · 链接状态：保投产
```

旧记录状态自动转换：

- `放弃` -> `保投产`
- `继续` -> `持续打爆`

### 推广调整

保留“新增调整”能力，每次调整仍是独立记录。每次调整保留：

- 调整原因
- 调整日期
- 操作概述，来源为原“投产 / 调整细节”字段
- 备注，来源为原“3-5天后数据反馈”文本字段
- 数据反馈，多图上传区

每次调整独立绑定自己的数据反馈图片，不能与其他调整或其他阶段的图片混合。图片选填，支持多张、拖拽、预览、排序和删除。

从每次推广调整中移除并清空旧值：

- 当前费比（7天）
- 当前付款人数（7天）
- 总预算

现有“投产 / 调整细节”和“3-5天后数据反馈”的旧文本分别迁移并继续显示为“操作概述”和“备注”，不丢失。

## 超级管理员配置

在超级管理员“系统配置”页面新增独立的“推广方式”配置区域，沿用现有上架类目配置的交互和服务边界：

- 新增、编辑、启用、停用、排序。
- 配置名称去除首尾空格，同名项不允许重复。
- 只有超级管理员可以维护。
- 其他角色只能查询启用项并在第二阶段搜索选择。
- 停用或删除配置不会改写已经保存的新记录文字；重新编辑时只能选择当前启用项。

推广方式使用独立配置表和独立服务/路由，不与上架类目或其他业务配置耦合。

## 图片存储

继续使用超级管理员配置的打款图片根目录和现有图片服务。新增图片用途：

- `potential_judgment`：绑定选品记录和第二阶段。
- `adjustment_feedback`：绑定选品记录、第三阶段和具体推广调整记录。

图片记录继续保存存储根目录、相对路径、原文件名、MIME 类型、大小、排序、上传人和软删除时间。推广调整图片需要可空的调整记录关联字段，保证每次调整的图片隔离。

图片规则：

- 只接受现有图片上传规则允许的文件类型和大小。
- 原文件名必须保留，下载或拖到桌面时继续使用原名称。
- 图片删除继续使用软删除，不直接删除物理文件。
- 阶段完成后只读；具备权限的用户重开阶段后可再次上传或删除。
- 图片上传失败不改变阶段状态，也不丢失已经保存的表单内容。

## 权限与并发

现有权限代码和店铺隔离规则保持不变：

- 普通用户继续只能查看同店铺可见记录。
- `payment.manage.all` 继续拥有所有店铺、所有人员记录的查看、编辑、删除、恢复和重开能力，创建记录时店铺显示“管理员”，策划人显示当前登录人员。
- 店长付费确认继续使用原店长审核权限。
- 阶段编辑、结束、恢复和重开继续使用既有权限判断。
- 乐观锁版本检查继续保护并发更新；冲突时返回明确提示，不覆盖其他人的修改。

本次不新增新的业务权限项。

## 数据库迁移

迁移同时支持本地 SQLite 和生产 MySQL，并通过后端既有启动初始化机制自动执行。迁移必须可重复执行，多次启动不会重复插入、破坏已迁移记录或报错。

迁移顺序：

1. 创建推广方式配置结构和新增图片关联结构。
2. 将 `preparation` 的付费确认数据迁入对应 `testing` 记录。
3. 将当前处于或结束于 `preparation` 的记录改为 `testing`。
4. 删除时间线中的 `preparation` 节点；需要时创建或合并 `testing` 节点，避免重复节点。
5. 回填有来源任务记录的选品时间。
6. 转换第三阶段旧链接状态。
7. 迁移保留并改名的推广调整文本。
8. 将当前处于或结束于 `breakout` 的记录阶段改为 `summary`，并按原状态创建或合并总结阶段节点。
9. 删除所有 `breakout` 时间线节点并清空 `payment_selection_breakout` 中的旧阶段业务记录。
10. 清空所有其他废弃字段和旧推广方式值。

若迁移未完成，业务服务不应在半迁移结构上继续提供打款跟踪功能。迁移错误必须记录具体步骤和数据库错误，便于在服务器电脑更新时定位。

## 接口与组件边界

- 来源任务打开服务负责读取并传递任务发布时间，不由前端拼接或推测。
- 工作流规则负责阶段顺序、第二阶段潜力款判断和第三阶段链接状态分支。
- 仓储层负责新字段、旧数据迁移、配置查询和调整图片关联。
- 推广方式使用独立配置服务与路由。
- 图片服务按图片用途和当前/重开阶段检查编辑权限。
- 第二、第三阶段表单只负责展示、输入和前端提示，不复制后端业务判断。
- 外层记录时间线继续消费阶段列表，不重写其视觉组件或点击行为。

## 错误处理

- 来源任务不存在或新建时缺少发布时间：拒绝创建来源记录并提示具体原因。
- 推广方式不存在或已停用：拒绝保存该值，提示重新选择。
- 图片用途、文件类型、大小或调整记录归属无效：拒绝上传，不改变表单和阶段状态。
- 用户无阶段、店长审核、图片或全局管理权限：返回权限错误，不写数据。
- 版本冲突：返回并发修改提示，要求刷新后重试。
- 数据迁移异常：停止进入业务运行阶段并输出可定位的迁移错误。

## 验证标准

### 后端与迁移

- 在本地 SQLite 新库启动时自动创建全部新结构。
- 在包含各阶段旧记录的本地 SQLite 副本上完成迁移，且第二次启动保持幂等。
- 准备阶段记录、时间线节点和付费确认数据迁移正确。
- 原第 5 阶段记录和业务数据已清空，原本停留或结束于该阶段的商品流程迁移到总结阶段。
- 有来源任务的选品时间正确回填；无来源任务或找不到来源任务的旧记录不被破坏。
- 废弃字段旧值和旧推广方式已清空。
- 第三阶段旧状态和推广调整保留文本映射正确。
- 每次推广调整的图片互相隔离。

### 工作流与权限

- 信息及选品直接进入第二阶段。
- 付费确认未通过、付费时间缺失或潜力款不符合时不能进入第三阶段。
- 保投产只能结束，持续打爆才能直接进入总结阶段，未选择只能暂存。
- 结束原因、恢复流程、重开历史阶段和不可见后续节点行为正确。
- 普通店铺隔离、店长审核和 `payment.manage.all` 全局权限保持原行为。

### 前端

- 外层时间线样式和节点点击交互与调整前一致，只展示新的四阶段流程。
- 信息及选品移除两个废弃字段，来源选品时间只读，手动新增仍可选时间。
- 第二、第三阶段字段、条件展示和提示与本设计一致。
- 推广方式支持包含文字搜索，只能选择已启用配置。
- 两类多图支持上传、预览、排序、删除和完成后只读。
- 桌面端和常用窗口尺寸下文字不溢出、控件不重叠、表单内容区域正常滚动。

### 执行限制

- 验证只使用本地 SQLite 和本地前后端。
- 不执行 `npm run build`、Vite build、Electron build 或任何安装包打包命令。
- 不推送远程仓库。
