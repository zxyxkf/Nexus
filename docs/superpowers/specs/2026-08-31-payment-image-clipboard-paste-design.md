# 打款跟踪图片截图粘贴设计

## 目标

在打款跟踪各阶段现有图片上传框中增加剪贴板截图粘贴能力，同时保留点击选择和拖拽上传。该调整只扩展图片进入上传框的方式，不改变图片存储、分类、预览、排序、删除、版本校验和阶段流程。

## 适用范围

所有使用 `ImageGallery` 的可编辑图片上传框统一支持粘贴：

- 信息及选品：产品主图、说明截图、竞品主图；
- 第二阶段：图片上传区；
- 第三阶段：链接优化图片上传区；
- 第三阶段每次推广调整：数据反馈图片。

只读状态不显示上传框，因此不提供粘贴入口。

## 交互

1. 使用者将鼠标移入可编辑上传框，现有悬浮高亮表示该框成为当前粘贴目标。
2. 使用者无需点击，直接按 `Ctrl+V`。
3. 当前悬浮上传框只读取剪贴板中的图片项，并将图片上传到自身对应的记录、阶段图片分类和调整记录。
4. 鼠标移出上传框后立即取消该框的粘贴激活状态。
5. 同一次粘贴包含多张图片时，按剪贴板顺序一次上传。
6. 剪贴板不包含图片时不调用上传接口，也不阻止文字等内容的正常粘贴。
7. 上传进行中禁用重复点击、拖拽和粘贴，沿用现有忙碌状态。
8. 点击上传框继续沿用原行为，打开系统文件选择窗口。

上传框提示文字调整为“拖拽图片到此处、点击上传，或鼠标移入后粘贴截图”，不增加额外按钮。

## 文件处理

剪贴板图片转换为浏览器 `File` 后继续调用现有 `uploadFileList` 上传路径。若剪贴板提供了有效文件名则保留；否则根据 MIME 类型生成 `clipboard-<时间戳>-<序号>.<扩展名>`，避免空文件名。常见 MIME 类型映射为 `png`、`jpg`、`webp`、`gif`，无法识别时使用 `png`。

文字、HTML 和其他非图片剪贴板内容不进入上传列表。现有后端继续负责图片格式、文件大小、文件数量、权限和版本校验。

## 组件边界

只修改共享组件 `src/components/payment-tracking/ImageGallery.vue`：

- 上传框通过鼠标进入和移出维护本组件的悬浮激活状态；
- 组件挂载期间监听页面 `paste` 事件，卸载时移除监听；
- 从 `clipboardData.items` 提取图片；
- 将图片交给现有 `uploadFileList`；

各阶段表单、图片 API 和后端不需要修改。页面可能同时存在多个 `ImageGallery` 实例，但只有鼠标当前悬浮的实例处理图片粘贴；其他实例立即返回，避免串入其他阶段或分类。只读实例和正在上传的实例不处理粘贴。

## 错误与并发

- 剪贴板无图片：不发送请求、不阻止事件默认行为；
- 图片无有效文件对象：跳过该项；全部无效时按无图片处理；
- 上传接口失败：沿用现有 API 错误处理；
- 版本冲突：沿用现有 `409` 提示和重新加载行为；
- 上传前需要保存推广调整：继续调用现有 `beforeUpload`，成功后使用返回的调整 ID 和版本上传。

## 验证标准

1. 鼠标悬浮任意可编辑上传框时粘贴截图，会调用现有图片上传接口，无需点击。
2. 请求 URL 中的图片分类与当前上传框一致。
3. 数据反馈粘贴继续携带正确的调整记录 ID。
4. 鼠标移出后粘贴截图不会上传；移动到另一个上传框后只由新上传框接收。
5. 同一页面多个上传框不会互相接收粘贴内容。
6. 粘贴纯文字不会发起上传，也不会阻止普通文字粘贴。
7. 点击选择、拖拽、预览、排序和删除行为保持不变。
8. 只读页面不具备粘贴上传能力。

## 执行限制

- 只使用本地前后端和本地 SQLite 验证；
- 不连接或修改生产数据库；
- 不执行前端或 Electron 打包；
- 不推送远程仓库，所有文档和代码提交仅保留在本地 Git。
