# 15.3.0 后功能可靠性修复设计

## 目标

修复 15.3.0 之后新增素材库、款式图快照、客服基础美工文件流转及筛选展示中的数据一致性、内存、权限和兼容问题，同时保持原有任务状态流转、角色边界和页面功能不变。

## 约束

- 仅在本地开发环境实施和验证，不连接生产服务器或生产数据库。
- 不执行前端构建、Electron 打包、提交或推送。
- 沿用 SQLite/MySQL 双数据库实现，所有数据库事务内操作必须使用事务回调提供的连接。
- 素材库上传继续独立于系统通用上传数量配置，不限制一次选择的素材数量。
- 只修改排查确认的问题，不扩展业务功能。

## 数据一致性

素材图片上传改为单请求、单事务处理。Multer 先把全部文件流式写入临时目录；服务层复制文件并通过同一个数据库事务插入全部图片记录。任一文件或 SQL 失败时回滚全部数据库记录、删除本批正式文件和临时文件。前端不再拆成多个 20 张批次，失败或响应不确定时重新加载当前款式图片。

素材删除采用“数据库事务先完成，物理文件随后清理”的顺序。数据库失败时物理文件保持不动；物理清理失败只产生可清理的冗余文件，不再形成数据库记录指向丢失文件的情况。素材排序更新全部使用事务连接。

素材目录修改沿用头像目录迁移模式：验证绝对路径和写权限，复制所有数据库引用文件，成功后切换配置并刷新缓存；失败时恢复旧配置并清理本次新复制文件。旧目录不自动删除，便于人工确认和回退。

任务发布改为单个 multipart 发布接口。任务数据、参考文件、素材选择清单和编辑后图片在一次请求中提交；后端在同一个数据库事务中创建任务和文件记录，并对落盘文件做失败补偿。只有事务成功后才发送通知和 Socket 更新，因此前端不会因后续上传失败而留下可见的残缺或重复任务。

## 上传资源控制

款式图编辑文件由内存存储改为磁盘临时存储，服务层按文件读取并在请求结束后清理。保留单文件上限和最多 200 张款式图限制，同时限制单请求编辑图片总量，避免单请求耗尽 Node 内存。

所有新增 multipart 流程统一使用 ASCII 传输文件名，原始文件名通过 UTF-8 JSON 字段传递。该规则覆盖款式图快照、客服新增修改、基础美工完成修改和原图上传。

## 权限

素材图片预览和下载要求当前用户具备素材库查看能力：`material.library` 或客服发布任务所需的 `task.create.cs`。响应使用私有缓存。

任务文件预览和下载先关联到任务，再复用任务详情权限规则校验当前用户。本人、任务执行人、同店铺运营、全量分区权限、打款开启查看范围、暂存任务权限和管理员规则保持与详情接口一致。

浏览器拖出图片时，下载地址必须携带当前登录 Token；Electron 继续使用已有缓存拖拽机制。

## 页面一致性

- 基础美工三个任务页面分别保存筛选条件，并在载入时清理当前页面不支持的状态值。
- 非客服发布任务页面不显示“待上传原图”。
- 批量下载 ZIP 按任务分区和文件类别使用明确目录名。
- 原图流程错误提示统一为中文。
- Playwright 文案断言同步当前“审核中/待审核/修改中”以及已移除的指定颜色功能。

## 验证

后端集成测试覆盖素材批次回滚、删除顺序、目录迁移、款式图磁盘上传、异常文件名以及任务/素材文件越权访问。前端测试覆盖任务发布单请求、页面筛选隔离、角色状态选项和下载分类。最后运行全部后端测试、JavaScript 语法检查和现有 Playwright 页面测试；不运行构建或打包命令。
