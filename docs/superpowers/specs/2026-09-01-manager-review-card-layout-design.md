# 店长审核卡片布局设计

## 目标

将店长审核页面从独立表格改为与选品收集、打款记录一致的商品记录卡片，消除同一业务分区内的视觉割裂。

## 范围

- 保留现有店长审核查询、店铺筛选、分页、详情弹窗、通过弹窗和拒绝确认逻辑。
- 复用 `ProductRowCard` 的商品主图、货号、店铺、策划人、产品 ID、来源任务、毛利、选品日期、待审核状态和阶段时间线。
- 店长审核卡片右侧竖排三个按钮：蓝色“查看记录”、绿色“通过”、红色“拒绝”。
- 待审核阶段节点保持只读，不能通过时间线进入编辑页面。
- 空列表、加载状态和移动端响应式行为与选品收集、打款记录一致。

## 组件方案

扩展 `ProductRowCard`，为调用方提供自定义操作区。未提供自定义操作区时继续渲染原有按钮，因此选品收集和打款记录的功能及展示不变。店长审核页面使用该操作区传入三个审核按钮。

店长审核列表接口目前只有表格摘要字段。列表接口将用批量查询附带只读的记录卡片摘要、产品主图和阶段时间线，前端不为每张卡片单独请求详情。点击“查看记录”继续调用现有审核详情接口；“通过”和“拒绝”继续调用现有决策接口。

## 验收标准

- 店长审核不再展示表格。
- 店长审核卡片与选品收集、打款记录视觉结构一致。
- 三个按钮按确认的颜色和顺序竖排。
- 通过仍要求填写付费时间；拒绝仍经过确认并结束流程。
- 审核完成后列表正常刷新，分页和筛选不受影响。
- 现有选品收集、打款记录按钮与流程没有回归。

## 非目标

- 后端只扩展店长审核列表响应的展示字段，不修改权限规则、审核状态机或数据库。
- 不改变详情弹窗内容。
- 不执行打包或推送远程仓库。
